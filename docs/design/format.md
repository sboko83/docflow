# Формат и раскладка

## Термины

- **Задача** — строка в Backlog `docflow.md`. Отдельного файла нет.
- **План** — `plans/Pxxx-slug.md`, создаётся при взятии задачи в работу.
- **Фаза** — группа юнитов, `Pxxx.N`.
- **Юнит** — единица выполнения за одну сессию, `Pxxx.N.M`.
- **Handoff** — записка для следующей сессии, пишется при закрытии юнита.
- **Архивная запись** — `archive/Pxxx-slug.md`, тот же id, что у плана; либо
  самостоятельная запись о решении без плана (`docflow note`).

## Раскладка в проекте

```
docs/
  docflow.md        # версия формата, очередь, backlog
  architecture.md   # жанр bsv-docs
  plans/Pxxx-slug.md
  archive/Pxxx-slug.md
```

Нумерация сквозная: следующий id = max по `plans/` и `archive/` + 1. Совпадение
id (два плана из разных веток) ловит `lint`.

`docflow.md` не автозагружается: в AGENTS.md только строка про `docflow status`.
Иначе растущий Backlog оплачивается на каждом запросе.

## Формат: общие правила

- Markdown. Frontmatter между `---`, только плоские `key: value` — без
  вложенности, списков и комментариев: собственный парсер CLI читает эту
  ограниченную форму; внешняя YAML-библиотека не нужна.
- Фиксированный набор H2 в фиксированном порядке, один для всех `type`;
  `lint` проверяет. Специфика типа (repro бага) — в `## Context` прозой или
  блоком кода: пункты `- ` там — ссылки на файлы ([P004](../archive/P004-plan-skill-fixes.md)).
- id юнита — в заголовке H3, статус — маркер перед id.
- Поля юнита — строки `Key: value` в начале строки; многострочное значение —
  список `- ` сразу под ключом. Строка с отступом продолжает пункт; значение
  в строке ключа продолжается до `Key:`, `- `, пустой строки или заголовка.
  Неизвестный ключ frontmatter и текст юнита вне полей — предупреждения
  `lint`, не ошибки. Почему — [P001](../archive/P001-docflow-cli.md).
- `docflow prompt` добавляет раздел `## Archive gotchas` перед `## Cycle`:
  пункты `## Gotchas` записей архива (`archive/Pxxx-….md`), на которые
  ссылаются `## Context`, `## Decisions` плана или текст диапазонов `Read:`
  юнита. Записи с `superseded_by` и отсутствующие файлы пропускаются; пункт —
  `- (Pxxx) <текст>`. Размер входит в прокси `read_budget` —
  [P009](../archive/P009-docflow-retro-fixes.md).
- Язык: ключи формата — английские; содержимое — русское; `Commit:` —
  английский.

Статусы: `[ ]` todo, `[~]` в работе, `[x]` готов, `[-]` пропущен,
`[!]` заблокирован (план устарел, нужно перепланирование).

### docflow.md

```markdown
---
docflow: 3
read_budget: 40000
start_read: README.md, docs/design/README.md
start_budget: 4000
---
## Queue
- P007
- P008

## Backlog
- Investigate cold start regression on iOS 18
```

`start_read` и `start_budget` необязательны (`docflow: 1` не меняется).
`start_read` — пути и `path#anchor` через запятую: что агент читает в начале
сессии. `start_budget` — целое > 0, токены (размер / 4); сумма `start_read`
выше бюджета — **ошибка** `lint` с размером каждого файла, отсутствующий файл
— тоже ошибка. `docflow status` печатает строку `start:` с `start_read`.
`init` пишет `start_read: README.md`, только если `README.md` есть.
Почему ошибка, а не предупреждение — [P009](../archive/P009-docflow-retro-fixes.md).

`whole_read_limit` (необязателен) — целое > 0, токены (размер / 4),
по умолчанию 4000. Целый файл сверх лимита в `Read:` открытого юнита
(`[ ]`, `[~]`, `[!]`) или в `## Context` плана с открытым юнитом —
**предупреждение** `lint`: размер файла и сумма Gotchas архивных записей,
которые тянутся за его ссылками. Чем лечить — диапазон `path:L10-80` или
`path#anchor`: за диапазоном наследуются ловушки только записей,
на которые он ссылается сам. Предупреждение, а не ошибка — целая ссылка
остаётся валидной у закрытых планов и в маленьких проектах —
[P047](../archive/P047-context-audit.md).

`preflight:` (необязателен) — команда проекта без кавычек, запускаемая из корня
перед `Verify:` каждого юнита. Ненулевой код прекращает проверку, удаляет прежний
отпечаток и возвращает код 4; раннер передаёт вывод агенту. Подходит для быстрого
lint без записи. `--no-gate` её не отключает; `--skip` пропускает все проверки.

`repos:` (необязателен) — glob от корня через запятую: вложенные git-репо,
которые корень игнорирует (`repos: modules/*, projects/*`). Репо — каталог
с `.git`; совпавший каталог без `.git` пропускается. Проверка чистоты на
`prompt` и отпечаток `verify` охватывают корень и каждый такой репо; пути
вложенных — с префиксом репо. `lint`: glob без репо — предупреждение, путь
вне корня (`..`, абсолютный) — ошибка; `*/.git` и `*/*/.git` вне `repos:` —
предупреждение. Сабмодули не поддерживаются — [P016](../archive/P016-nested-repos-freeze.md).

Queue — только порядок; путь находится по id, slug можно переименовать.
`## Frozen` (необязательна, между Queue и Backlog) — замороженные планы:
пункт `- Pxxx — <причина>` или `- Pxxx`, id — первое слово. Пишут её
`docflow freeze` и `thaw`. План со `status: frozen` — только в Frozen,
остальные — только в Queue, id в обеих секциях — ошибка `lint`. Замороженный
план вне очереди: `status`, `next`, `run` его не видят, `prompt`/`verify`/
`done` по id — ошибка; ссылки `Read:` и Context `lint` у него не проверяет — [P016](../archive/P016-nested-repos-freeze.md).
Backlog — свободный текст, правится руками; строка удаляется, когда по ней
создан план. При закрытии в него уходят Follow-ups после разбора: несделанное
из Goal — всегда, остаток брошенного плана, а открытый `Unverified:` — только
когда это разрыв с Goal или риск с конкретным падающим сценарием. Только в
записи остаются: наблюдение вне Goal, которому нечего делать до внешнего
события, — строкой `Waits: <событие> — <что сделать>`, список таких —
`grep -rn 'Waits:' docs/archive` ([P031](../archive/P031-backlog-actionable.md));
и принятый риск — строкой `Accepted: <пункт> — <почему это не риск>`
([P044](../archive/P044-unverified-discipline.md)).

### План

````markdown
---
id: P007
title: Offline cache for feed
type: feature
status: active
created: 2026-10-12
executor: codex | gpt-5.5 | high
---
## Goal
## Context
## Constraints
## Traps
## Decisions

## Phase 1: Storage layer

### [x] P007.1.1 Add SQLDelight schema
Read:
- shared/src/commonMain/kotlin/feed/FeedRepository.kt:L1-80
- docs/architecture.md#storage
Do:
- ...
Verify: `./gradlew :shared:allTests`
Traps: ...
Depends: -
Executor: claude | claude-opus-5-5 | -
Commit: P007.1.1: add feed cache schema
Handoff:
- <filled by docflow done>
````

- Поля юнита в фиксированном порядке: `Read`, `Do`, `Verify`, `Traps`,
  `Depends`, `Executor`, `Model`, `Role`, `Commit`, `Handoff`. Обязательны `Read`,
  `Do`, `Verify`, `Commit`; `Handoff` пишет только `done`.
- Исполнитель — `executor: agent | model | effort` во frontmatter плана и
  `Executor: agent | model | effort` в юните, одной строкой; пробелы вокруг
  `|` допустимы. `agent` — `claude`, `codex`, `pi` или `opencode`, `model` — полное имя модели
  без пробелов и `|`, `effort` — одно слово либо `-` (усилие не передаётся).
  Значение юнита целиком заменяет значение плана. Хоть одно назначение — и
  каждому юниту `[ ]`/`[~]`/`[!]` нужна полная тройка из себя или шапки, а
  `Model:` у них — ошибка; `[x]` и `[-]` остаются как история. Пустой
  компонент, не 2 разделителя, неизвестный агент, многострочное значение,
  дубль — ошибки `lint`. Доступность модели в аккаунте `lint` не проверяет.
  Пустой скелет `docflow new` назначения не содержит: его ставит автор плана.
- Роль юнита — `Role: cheap|heavy|review|acceptance` вместо `Executor:`:
  цепочка маршрутов берётся из ключа роли в шапке, `fallback:` к ней не
  добавляется. Роль — одно слово из списка, одной строкой; `Role:` вместе
  с `Executor:`, роль без своего ключа в шапке и роль вне режима
  исполнителей — ошибки `lint`; ключ роли без юнитов с этой ролью —
  предупреждение. Юнит с `Role:` не наследует `executor:` шапки
  ([P036](../archive/P036-roster.md)).
- `Model:` — только в плане без Executor (legacy), необязательно, одно
  слово: ярус `fast|default|strong|max` или id модели. Смысл задаёт конфиг
  раннера (ярус → модель ассистента); поля нет — модель профиля по
  умолчанию.
- `Verify:` — всегда команда в обратных кавычках, без «проверить вручную»:
  юнит с текстом (скилл, док) проверяется `docflow lint`, `grep`, тестом.
- `Depends:` — id юнитов этого плана через запятую или `-`. Межплановых
  зависимостей нет: порядок планов задаёт Queue.

- `type`: `feature|bugfix|perf|module|refactor`.
- `gate:` — необязательно: команда без кавычек, которую `verify` запускает
  после `Verify:` каждого юнита плана — [P014](../archive/P014-verify-gate.md).
- `permissions: auto|full` — необязательный ключ режима прав прогона
  `docflow run`; нет ключа — `auto`, нынешние аргументы агентов. `full`
  снимает подтверждения и песочницу, поэтому раннер спрашивает подтверждение
  y/N один раз на старте прогона: ключ в файле плана сам по себе песочницу
  не снимает.
- `replan: agent | model | effort; ...` — необязательная цепочка, каждая
  тройка — как у `executor` выше: исполнители перепланирования блока «нужна
  правка плана» и устаревшей ссылки `Read:`. При отказе маршрута раннер
  идёт по цепочке; `fallback:` к ней не добавляется. Нет ключа — блок
  останавливает прогон. Только в плане с исполнителями; повтор
  `agent|model` в цепочке — ошибка, цепочка из одной тройки —
  предупреждение `lint`. Почему без `fallback:` — ([P036](../archive/P036-roster.md)).
- `fallback: agent | model | effort; ...` — необязательная упорядоченная
  цепочка резервных маршрутов после основного `executor:`; только в плане
  с исполнителями. Каждый элемент — полная тройка, повтор основного
  `executor:` запрещён. `run --dry-run --all` печатает цепочку после
  маршрутов юнитов. Поведение при отказах — в разделе
  [резервные маршруты и таймаут раннера](runner.md#резервные-маршруты-и-таймаут).
- Ключи ролей `cheap:`/`heavy:`/`review:`/`acceptance:` — необязательные
  цепочки `agent | model | effort; ...` на роль, только в плане с
  исполнителями: юнит с `Role: heavy` идёт по цепочке `heavy:` вместо
  `executor:` и `fallback:`. Каждая тройка разбирается как `executor`;
  повтор `agent|model` в цепочке — ошибка, цепочка из одного маршрута и
  ключ без юнитов с этой ролью — предупреждения `no fallback for
  <роль>` / `no units with role <роль>`. Роль executor остаётся на
  `executor:` + `fallback:`, роль replan — на `replan:`.
- `timeout: 60..86400` — необязательный целый таймаут в секундах для вызовов
  агента в юнитах и replan; перекрывает `timeout` профиля в любом режиме.
  Подробности — [в разделе раннера](runner.md#резервные-маршруты-и-таймаут).
- `## Prerequisites` — необязательная секция между `## Constraints` и
  `## Traps`: что обеспечивает человек до прогона. Пункт — `- текст` или
  `` - текст: `команда` ``; необязательная метка ` (once)` в конце пункта
  разрешена в обеих формах. Команду раннер выполняет на старте прогона до
  квоты и агентов; пункт без команды показывается в том же подтверждении
  старта. Метка `(once)` означает, что предусловие проверяется только до
  старта плана; при продолжении начатого плана раннер пропускает пункт
  ([P033](../archive/P033-prereq-once.md)).
  План начат, если хотя бы один юнит имеет статус, отличный от `[ ]` и
  `[-]`. Секреты в план не пишутся: предусловие называет, где лежит
  значение (переменная окружения, файл вне репозитория), но не значение.
- Версия формата — 3. Старый CLI (версии 2) отвергает проект с маркером 3:
  код 2 и подсказка `docflow migrate`, которую он сам не выполнит, —
  обновление CLI вместо тихой деградации. Клиент, который знает
  `## Prerequisites`, но не метку `(once)`, воспринимает отмеченный
  пункт как текст без команды и показывает его в подтверждении старта;
  клиент, который не знает секцию, отвергает её ошибкой `lint` — громко,
  не тихо ([P025](../archive/P025-autonomous-run.md)).
- `status`: `draft|active|frozen`; `frozen` ставит `docflow freeze`. Состояний done/dropped у файла нет: закрытый или
  брошенный план уходит в архив и удаляется.
- `new` создаёт `draft`; `next` и `prompt` черновики пропускают. В `active`
  план переводит только `docflow activate` после чистого lint плана;
  запускает её человек, агент — по прямой просьбе. Скилл планирования
  останавливается на `draft` —
  [P017](../archive/P017-manual-plan-activation.md).
- `## Context` — доки и файлы, нужные каждому юниту. `## Traps` — ловушки
  всего плана. `## Decisions` — пополняется по ходу работы, источник для архива.
- `Read:` — точные пути; допустимы `path:Lstart-end` и `path#anchor`.
  Markdown-ссылка `[t](path)` здесь и в `## Context` — ошибка `lint`.
  Файл, который создаст более ранний юнит: `lint` — предупреждение,
  `prompt` — ошибка.

Требование к юниту: понятен слабому агенту без чтения чата — что читать,
что делать, чем проверить, какие ловушки, каким сообщением коммитить.

### Архивная запись

```markdown
---
id: P007
title: Offline cache for feed
closed: 2026-11-02
---
## Outcome           <!-- 2–3 строки: что теперь есть -->
## Decisions         <!-- решение — почему — отвергнутая альтернатива -->
## Gotchas           <!-- ловушки, актуальные после закрытия -->
## Follow-ups        <!-- несделанное; в Backlog — всё, кроме `Waits:` и `Accepted:` -->
```

Необязательный ключ `superseded_by: Pxxx` — ставится, когда новый план
отменяет запись целиком (раздел [«Архив»](archive.md#архив)); `lint` проверяет только формат id.

Диапазона коммитов нет: коммиты разных планов перемешаны в main, после
squash-merge хэши пропадают. Связь — префикс `P007.` в subject.

## Версии формата

- Версия только в `docflow.md` (`docflow: N`), у планов своей нет.
- Скрипт читает только текущую версию; на старую — код 2 и подсказка
  `docflow migrate`. `migrate` знает все прежние версии.
- 2 — исполнитель в плане (`executor:`/`Executor:`): CLI версии 1 отвергает
  такой проект, а не игнорирует назначение. Миграция 1 → 2 меняет только
  маркер; планы, их `Model:` и архив не трогает
  ([P021](../archive/P021-plan-executors.md)).
- 3 — цепочки на роль: ключи `cheap:`/`heavy:`/`review:`/`acceptance:` в
  шапке, `Role:` в юните, `replan:` — цепочка. Миграция 2 → 3 меняет маркер
  и дописывает маршруты `fallback:` в `replan:` планов из `docs/plans/`
  (архив не трогается); планы без `replan:` и `fallback:` не меняются —
  старые планы сохраняют поведение запасных маршрутов ([P036](../archive/P036-roster.md)).
