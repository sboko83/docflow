# Эталонный бенчмарк

Бенчмарк измеряет, как изменения docflow влияют на выполнение фиксированных
задач. Общая база находится в `bench/base/`, а план, скрытый оракул и эталонное
решение каждой задачи — в `bench/tasks/<name>/`. Модуль `bench/go.mod` не даёт
фикстурам Go попасть в сборку основного модуля.

## Проверка корпуса

`go run ./tools/bench validate --task NAME` сначала проверяет план через
`docflow lint`, затем запускает `go test -json ./benchoracle/...` отдельно на
копии базы и на копии базы с наложенным решением. Оракул должен провалиться на
базе и пройти на решении; количество пройденных тестов служит оценкой ветки.
Оракул лежит отдельно от проекта-копии и не доступен модели во время задачи.

## Прогон

`go run ./tools/bench run --task NAME` запускает ветки `single` и `docflow`.
`single` получает весь план за одну сессию Codex; `docflow` исполняет план
через `docflow run` и ростер `bench/roster.toml`. Ветка `docflow-one` доступна
в `--arms` для сравнения цикла без смены маршрутов. По умолчанию CLI docflow
собирается из текущего checkout; `--docflow PATH` указывает другой бинарь.
`--dry-run` показывает выбранные задачи, маршруты и рабочие пути без запуска
агентов и записи результатов.

Каждая ветка получает отдельную копию только `bench/base/`. После завершения
ветки на её дереве запускается оракул. Логи и копии остаются в локальном
`work/bench/<run-id>/`; ветка не получает каталог задач, оракул или историю
docflow.

## Результаты

`bench/results/runs.jsonl` хранит по записи на задачу и ветку. Каждая запись
имеет `v: 1`, идентификатор и время прогона, SHA задачи и ростера, сведения о
версии и коммите docflow, статус, счёт оракула, время, стоимость, токены,
метрики юнитов и изменения дерева. Результаты и сгенерированный
`bench/results/README.md` коммитятся вместе; перед прогоном каталог результатов
должен быть чистым. Сводка конкретного прогона находится в
`bench/results/<run-id>/`.

README показывает результаты по задаче и ветке, сравнивает оценку оракула и
стоимость с предыдущим прогоном той же задачи при неизменном SHA задачи. Для
новой версии задачи изменение отмечается отдельно, без сравнения оценок как
эквивалентных.
