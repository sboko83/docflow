## Outcome           <!-- 2–3 строки: что теперь есть -->
`bsv-docflow-plan` задаёт нижнюю границу размера юнита (объединять, пока
укладываются в ~100k, 5–8 файлов, один `Verify`) и велит писать repro в
`## Context` прозой; `lint` у проблемной ссылки в Context даёт подсказку.

## Decisions         <!-- решение — почему — отвергнутая альтернатива -->
- Repro в `## Context` — прозой или блоком кода, пункты `- ` остаются
  ссылками; `lint` только подсказывает — формат не меняется, `prompt`
  уже передаёт весь Context как есть — отвергнуто: подраздел `### Repro`
  или эвристика «пункт не похож на путь» в `context_refs` (новое правило
  формата ради одного жанра, ложные срабатывания).
- Нижняя граница размера юнита — правило скилла, не проверка `lint` —
  объединять мелкие юниты может только планировщик, `lint` не знает, какие
  юниты сливаемы — отвергнуто: warning `lint` на юнит меньше N токенов.

## Gotchas           <!-- ловушки, актуальные после закрытия -->
- Пункт `- ` с прозой в Context — warning `file not found`, не error:
  `REF_RE` принимает почти любой текст как путь; error только при якоре
  или диапазоне строк.
