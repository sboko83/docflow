## Outcome

Unix shell fixtures `internal/runner` и `internal/agentio` работают на
Windows: весь `go test ./...` зелёный на Windows 11 (Git for Windows),
включая интеграционные прогоны раннера на fake-агентах. Убийство дерева
процессов переведено с `taskkill /T /F` на kill-on-close Job Object —
`taskkill` по родительским PID не видит потомков MSYS. Вопрос старта о
human-блоке проверяется автоматическими ConPTY-тестами; полный parity и обе
установки проверены на Windows. Linux/macOS после изменений не проверялись
(кросс-компиляция и vet — да).

## Decisions

- Дерево процессов на Windows завершается Job Object: `procgroup.Track`
  кладёт процесс в kill-on-close джоб сразу после старта, `Kill`
  терминирует джоб, фолбэк — прежний `taskkill /T /F`, затем
  `Process.Kill`; подтверждено опытным путём: MSYS2 создаёт потомков через
  короткоживущий хелпер, их Win32-родитель умирает до убийства дерева,
  `taskkill /T` их не находит, они переживают `taskkill /T /F` (и держат
  трубы вызова до полного `WaitDelay` — 5 с на каждое принудительное
  убийство) — отвергнуто: продолжать `taskkill`-only, тесты про
  таймаут/столл на Windows; x/sys/windows вместо сырого `syscall` —
  проверенные структуры JOBOBJECT, отказ P040 от Job Objects «через
  syscall» относился к ручной реализации, а не к любой.
- Дочерние вызовы агентских шимов идут через компилируемый exe
  (`internal/testshim`), который передаёт аргументы NUL-разделённым
  файлом и прологом восстанавливает `"$@"` — хоп «нативный процесс →
  MSYS bash» теряет аргументы с кавычками при любой командной строке
  (схема агента всегда с кавычками), а `.cmd`-шим ломает их ещё раньше —
  отвергнуты `.cmd`-фронт и проброс аргументов argv.
- Закрывающий промпт даёт агенту абсолютный путь работающего CLI
  (`'<cli>' close P001`, `'<cli>' lint`) — PATH внутри оболочки агента
  раннеру не подконтролен (MSYS-конвертация переставляет записи, профиль
  может заменить PATH); `closeEnvironment` остаётся подстраховкой, плюс
  починен фильтр `PATH=` (Windows пишет переменную как `Path`, старое
  значение выживало рядом с новым и выигрывало) — отвергнут расчёт
  только на prepend собственного каталога в PATH.
- Относительные пути логов вызова в стриме событий и в строке прогресса
  — с прямыми слешами — поток машинно-читаемый, parity сравнивает вывод
  на разных ОС; вывод вне событий остаётся нативным.
- Фейковый агент на Windows ищется настоящим exe-шимом ещё и потому, что
  новейшие сборки Windows исполняют shebang-скрипты, а Go `LookPath`
  находит файлы без расширения — поведение платформы расходится между
  машинами, фикстуры не должны на него опираться.

## Gotchas

- Хоп «нативный процесс → MSYS bash» портит argv с кавычками и `&&`
  независимо от кавычкования; MSYS→MSYS (bash внутри bash) — цел.
  Аргументы с кавычками через командную строку в MSYS не передать.
- `UpdateProcThreadAttribute` с `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`
  несёт само значение хендла, а не указатель на него; запуск с
  `&handle` даёт ребёнку 0xC0000142. Ребёнок ConPTY наследует
  (невалидные) значения std-хендлов родителя: чтобы `os.Stdin` был
  консолью, хост должен обнулить свои слоты `SetStdHandle` перед
  `CreateProcess`.
- `go test`-процесс под ConPTY видит все три потока консолью; собирает
  вывод драйвер, читающий выходную трубу ConPTY до её закрытия.
- Установленный в PATH `.docflow\current` перехватывает `docflow` в
  фикстурах, если шаг обращается к CLI по имени: шаги close в тестах
  зовут абсолютный путь бинарника.
- `internal/testshim` строит шим-exe один раз на процесс в
  `%TEMP%\docflow-shim-*` и копирует его под каждым именем; скрипт шим
  выводится из пути exe (`claude.exe` → `claude`).
