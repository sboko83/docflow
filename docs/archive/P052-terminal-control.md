title: Interactive terminal control for plan execution
closed: 2026-11-02

## Outcome
`docflow tui` — полноэкранное рабочее место в том же бинарнике: дерево Queue и
планов, живая история сообщений, инструментов, изменений и проверок, выбор
моделей и исполнителей до старта, Pause / Stop after unit / Stop now,
восстановление по checkpoint и Continue после human-блока поверх общего
раннера. Проверено PTY-приёмкой на macOS, pseudo console на Windows и
живым прогоном Pi и Codex на Mac; PTY-приёмка на Linux после исправления
зависания и живые агенты на Linux и Windows не подтверждены.

## Decisions
- TUI — команда `docflow tui` основного бинарника на Bubble Tea v2.1.1 и Lip
  Gloss v2.0.6 (модули `charm.land/...`), минимальный Go поднят до 1.26 —
  единая установка и общий раннер; отвергнуты веб-интерфейс, отдельный
  `docflow-tui` и устаревающая ветка Bubble Tea v1.
- `runner.Control` — единственная точка команд интерактивного хозяина и
  ограниченная очередь событий поверх существующего `Run`/`runLoop`: медленный
  UI не задерживает раннер; второй цикл исполнения отвергнут. Интерактивный
  прогон не читает stdin и не пишет Progress — терминалом владеет только UI.
- Checkout lock принадлежит `StartCheckout` на весь `execute`; второй
  владелец с живым pid отказывается даже при том же pid, а `release` удаляет
  файл, только если в нём ещё наш pid — отвергнуты вложенный захват и
  безусловное удаление. Lifecycle-действия UI идут через `cycle.Self`,
  который lock не берёт, поэтому UI перечитывает lock в момент каждого
  действия; нечитаемый lock — отказ, а не «свободно».
- Pause — отдельная причина отмены, а не отказ провайдера или попытка:
  классифицируется до обработки отсутствующего result JSON, не тратит
  попытку и не запускает fallback; verify/gate и done/commit доходят до
  устойчивой границы (`stage: complete`). Записанный checkpoint —
  единственный признак паузы для `unit_end`, `run_end`, отложенных
  `replan`/`close` и перехода хоста в Paused; ошибка записи — код 2 и Failed.
  Отвергнуты SIGSTOP (оставляет инструменты работать) и повторное вычисление
  состояния Pausing в каждом эмиттере.
- Журнал паузы и остановки: `unit_end.status: paused|stopped`,
  `run_end.reason: paused|stopped`, `exit_code: 0`, поле `paused` только под
  паузой; отложенные `replan`/`close` несут `result: paused|stopped` через
  общий `controlOutcome`. Сигнал и отмена родителя остаются `error`/2 —
  отвергнуто переиспользование внутренних кодов 7/2 как маркеров.
- Checkpoint хранит остаток timeout (не прошедшее время, иначе повторные
  resume вычитают дважды), тройку agent/model/effort, session id и
  checkout-relative логи. Resume продолжает сессию только на той же тройке;
  при расхождении или отвергнутом resume (распознаётся по тексту провайдера)
  ровно одна новая сессия с полным промптом и сводкой прерывания.
- Пауза во время replan откатывает план до правки агента; любой
  незавершённый вызов replan (Stop now, сигнал, ожидание отказа) тоже
  откатывает план. Checkpoint replan/close не возобновляется — восстановление
  просит новый запуск; пауза в close дерево не откатывает (агент мог уже
  архивировать план) и просит `git status`. Отвергнуты checkpoint поверх
  правки агента и автоматический `git restore`.
- Stop now — отдельная команда `Control.StopNow` без checkpoint; Stop after
  unit идёт через stop-файл, который управляемый прогон не удаляет, а хозяин
  снимает до `MarkRunning`. Отменённый старт (`CancelStart`,
  `MarkStartCancelled`) — состояние Cancelled, не Finished и не Paused.
- Активность — нормализованный поток `agentio.Activity` (Codex, Claude, Pi,
  OpenCode) только при интерактивном хозяине; журнал получает ссылки
  `stream` и снимки `config`/`state`, а не событие на каждую строку агента —
  отвергнуты fsync на строку и дубли тел сообщений. stderr пишется в
  sidecar `<call>.stderr`, исходный лог байт-в-байт; лог verify —
  `verify.<uid>.<n>.out` вне пространства `uid.*.out`. Большой ввод
  инструмента клипуется с запасом 256 байт и маркером `{"truncated":true,
  "bytes":N}`.
- Лог записи истории фиксируется при её приходе из события `attempt`
  (выходит до `CallAgent`, `stream` — после); живая страница читает от
  смещения до текущего конца файла (`ReadLiveActivityPage`), `Ref.Length`
  остаётся длиной строки — отвергнуты ранний `stream` и расширение формата
  ссылки. Пути из событий разрешаются от корня checkout в момент чтения.
- История — один упорядоченный список `runner.Event`; рендер — окно в 200
  записей вокруг курсора, не более 8 страниц по 4 KiB в памяти, diff до
  512 KiB. Ручное движение снимает follow, `G`/`f`/`End` возвращают; follow
  двигает видимую панель при любом фокусе; смена юнита включает follow.
- UI опрашивает `Controller` (polling), а не держит команду ожидания на
  канал; одно стартовое подтверждение даёт раннер (`StartReview`) с
  назначениями, предусловиями и лимитами — отвергнут второй pre-flight в UI.
  Поздний prompt запоминается до закрытия открытого диалога.
- Конфигурация моделей прогона — overlay явных переопределений ролей и
  юнитов плюс эффективный снимок в `<git-dir>/docflow/tui/configuration.json`;
  план и ростер не переписываются, обычный `run` её не читает и сохраняет
  запрет `--model` в executor-режиме. Устаревшие переопределения (юнит
  `[x]`/`[-]`, чужой план, неиспользуемая роль) снимаются при чтении, а
  `ValidateConfiguration` по-прежнему отказывает новой правке завершённого
  юнита.
- Лимиты управляемого прогона — флаги `docflow tui --attempts/--replans`
  (3/3 по умолчанию), видимые в стартовом диалоге; отвергнута env-переменная
  только для драйвера приёмки.
- Восстановление классифицирует раннер (`LoadRecovery`: checkpoint + сводка
  последнего журнала, сверка плана, юнита, HEAD и fingerprint); диалог
  открывается один раз за сессию, pending commit доводится существующим
  циклом, завершённый юнит Continue не предлагает.
- Выход по SIGTERM/SIGHUP идёт после `program.Run` тем же путём Pause →
  Finished → Close, что `q`: Bubble Tea превращает SIGTERM в QuitMsg, а
  SIGHUP ставится файлом под build tag (на Windows его нет).
- Геометрия экрана — одна функция `bodyHeightFor` от отрисованного тела с
  notice-строками; notice исхода — до двух строк над статусной, ключи
  диалога прижаты к низу, тело диалога прокручивается.
- Живая приёмка — `tools/tui-live.sh --run/--check` на временном проекте вне
  checkout, квитанция в `<git-dir>/docflow/tui-live/` привязана к HEAD и
  SHA-256 бинарника, бюджет вызовов следит за журналом во время прогона.
  Владелец разрешил шесть вызовов Codex на попытку приёмки после дефекта
  драйвера, найденного живым прогоном.
- Ревью фаз P052.1.4 и P052.2.4 блокировались 5 и 10 раз; десятый блок и
  находки проверки перед закрытием исправлены напрямую (P052.2.24,
  P052.4.3) по решению человека — открытое ревью выбирает из пула дефектов,
  а не исчерпывает его.

## Gotchas
- Чтение master PTY в отдельной горутине не прерывается `Close`; на Linux
  EIO приходит только после закрытия всех копий slave — родитель закрывает
  свою копию после `Start`, иначе тест висит до таймаута пакета.
- Bubble Tea и conhost (Windows pseudo console) перерисовывают только
  изменённые ячейки: текст проверяется по восстановленному экрану
  (`acceptTerminal` в `internal/tui/screen_test.go`), а не по сырому потоку.
- Высота тела и высота контента панели различаются на строку заголовка и
  notice-строки; видимость проверяется по отрисованному экрану.
- Pi сообщает вызов инструмента дважды (`tool_execution_end` и `toolResult`
  в следующем `message_end`); парсер закрывает id один раз.
- На Windows `filepath.Rel` даёт `..\`, а `os.UserHomeDir` читает
  `USERPROFILE`, не `HOME`; короткие пути 8.3 (`RUNNER~1`) раскрываются
  `EvalSymlinks` в длинные.
- Фейковый агент в тестах паузы пишет маркер «стартовал» после вывода, от
  которого зависит проверка (session id, pid дочернего процесса): bash на
  Windows медленный, и пауза на раннем маркере обгоняет вывод. `$!` в Git
  Bash — MSYS pid; живость проверяет `kill -0` той же оболочки.
- Переопределения моделей в `configuration.json` общие для checkout: старт
  одного плана снимает переопределения юнитов и ролей другого плана.

## Follow-ups
- Accepted: пауза в окне между юнитами — ветка верхней проверки `runLoop`,
  общая с `TestPauseAfterReplanCommitIsFinished`; без checkpoint прогон
  честно завершается Finished, следующий юнит не стартует.
- Accepted: отказ записи checkpoint в отложенных replan/close и пауза внутри
  git-команды коммита — тот же `pauseCheckpoint` и seam после коммита, что
  проверены на пути юнита; новых веток нет.
- Accepted: Stop now в восстановлении pending commit — журнал исправляет
  отложенная классификация, проверенная моделью; гонка `q`/Enter при старте
  покрыта фиктивным контроллером, реальный переход проверен живым прогоном.
- Accepted: интерактивный старт из установленного релиза — тот же бинарник и
  тот же путь `cycle.Self`, что у `docflow run`, который release workflow
  проверяет на установленном релизе; installer проверяет `tui --help`.
- Accepted: тестовый ANSI-эмулятор покрывает последовательности текущих
  Bubble Tea и conhost; смена рендерера — обслуживание тестов.
- Waits: рабочий проект на Linux или Windows запускает `docflow tui` с живым
  агентом — проверить там паузу, продолжение и остановку дочерних процессов
  (на Mac проверено живым прогоном, на Linux — PTY-приёмкой CI, на Windows —
  pseudo console с фиктивным агентом).
- Waits: первый push после закрытия — CI впервые прогоняет PTY-приёмку на
  Linux после исправления зависания читателя PTY; красный результат —
  исправить сразу, а не переносить в Backlog.
- Accepted: тесты-изменения P052.4.3 — перенос эмулятора и фикстуры в общие
  файлы, перестановка строк фикстур паузы, бюджет zai-пробы 1 → 2 с с
  сохранённой границей; ни одна проверка не ослаблена.
