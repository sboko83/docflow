id: P050
title: Verify guard against self-weakened checks
closed: 2026-10-29
---
## Outcome
Replan в раннере не трогает опорные проверки: `Verify:`, `Do:`, `Role:`
юнитов review/acceptance, их переход в `[-]` и пометку открытого юнита `[x]`
`check_replan` отклоняет, а смены `Verify:` и `[-]` обычных юнитов docflow
сам пишет в `## Decisions` (`Replan changed check:`), в сводку и событие
`replan`. Коммит юнита помечает ослабленные тесты блоком `Test changes:`;
пункты видны в выводе `docflow commit`, в прогоне и в разделе
`## Test changes` промптов review и acceptance. Linux и macOS проверяет
только CI-матрица.

## Decisions
- Опора и прозрачность вместо запрета: юниты review/acceptance и `gate:` —
  опорные проверки, их replan не трогает; смена `Verify:` обычного юнита
  разрешена, но записывается docflow, а не агентом — отвергнут стоп на
  человека при любой смене `Verify:` (убивает автономность на устаревших
  путях).
- Правки тестов помечаются, а не запрещаются: легитимный рефакторинг меняет
  тесты — отвергнута заморозка тест-файлов юнита (новый ключ формата,
  ложные блоки).
- Сигнал правки тестов живёт в теле коммита юнита: git — источник правды
  для ревью, приёмки и бенчмарка, работает и в интерактиве, и в раннере;
  промпт читает пункты из тел коммитов, раннер — из stdout `docflow commit`,
  никто не пересчитывает дифф заново — отвергнуто поле только в событии
  (теряется в интерактиве) и пересчёт в раннере или промпте (расхождение с
  телом коммита).
- Опорные поля сравниваются сырым текстом поля (ловит переписанный список
  `Do:` и удалённую строку `Role:`), роль берётся из старого плана
  (удаление `Role:` — проблема `Role changed`, а не тихий выход из опоры);
  обычные юниты — по значению `Verify:`, чтобы пункт показывал старое и
  новое — отвергнуто сравнение опоры по `field.Value` (список `Do:` им не
  покрыт).
- Открытый юнит не может стать `[x]` через replan — для всех юнитов, не
  только опорных: раннер `[x]` пропускает, проверка исчезла бы молча (обход
  нашло ревью P050.1.3) — отвергнута запись перехода пунктом
  `Replan changed check` (создавала бы видимость пройденной проверки).
- Записывается только то, что replan прошёл: смены опоры и истории
  останавливают вызов, удалённому юниту хватает `unit removed` — отвергнута
  запись отклонённых смен (план восстанавливается, запись ушла бы в
  корзину).
- Пункты для коммита, сделанного до сбоя, восстанавливаются по его
  собственному диффу (`before..HEAD`), а не по индексу: индекс после сбоя
  чист, и сверка тела отклоняла бы законный коммит — отвергнут `expected`
  без блока `Test changes:`.
- Дифф разбирается через `git diff -M --numstat -z` и `--name-status -z`:
  чистое переименование не даёт пункта, пути без кавычек и `{a => b}` —
  отвергнут разбор текстового numstat.
- Skip-маркер — подстрока в добавленной строке патча, построчно: маркеры
  языконезависимы — отвергнут разбор AST каждого языка (зависимости,
  правила на язык); маркер, разнесённый по строкам, не ловится.
- Без новых ключей формата и событий: блок в теле, строки
  `test change: ` хвостом вывода (sha юнита раннер берёт первым словом),
  новые поля `check_changes`, `test_changes` в событиях `v: 1`; `unit_end`
  несёт `test_changes` всегда, 0 когда пунктов нет — отвергнуто опускать
  поле (разная форма событий в одном прогоне).
- `## Test changes` строится тем же диапазоном и фильтром по префиксу и
  юниту, что `## Phase diff`, и тем же кодом подразделов `repos:`; `repos:`
  читается и для acceptance — отвергнут весь диапазон `base..HEAD` без
  фильтра (в промпт review попадали чужие фазы).
- Правило об опоре дописано в конец правила 3 `replanRules` и зеркалится
  концом правила 3 и пунктом «Replan under the runner» скилла
  `bsv-docflow-plan`; паритет проверяется инвариантными фразами — отвергнут
  новый нумерованный пункт (сдвиг нумерации, которую зеркалит скилл) и
  побайтовое сравнение текстов.
- Скилл run перечисляет skip-маркеры из `skipMarkers` явно: агент знает,
  что поймает детектор — отвергнут запрет общими словами.

## Gotchas
- Правила replan живут в двух местах: `internal/runner/replan_rules.go`
  (правило 3) и `skills/bsv-docflow-plan/SKILL.md` (правило 3 «Replan» и
  «Replan under the runner»). `TestVerifyGuardReplanRulesSkillParity`
  сверяет только фразы «the runner skips a `[x]` unit», «`Role: review`»,
  «`Role: acceptance`» и «Replan changed check» — их нельзя разрывать
  переносом строки.
- Формы `<path>: -N lines`, `<path>: deleted`, `<path>: +skip`, строка
  вывода `test change: <пункт>` (`<repo>/<пункт>` у вложенного репо), строки
  `- <subject>: <пункт>` раздела `## Test changes` и
  `Replan changed check: <id> Verify: <old> -> <new>` / `<id> skipped`
  читают скиллы run/plan, `docs/usage.md` и тесты раннера; правка формы —
  во всех местах сразу.
- Коммит, сделанный бинарником без P050 и прерванный до вывода, при
  возобновлении новым бинарником даёт `unexpected HEAD`, если его дифф
  содержит пункты: ожидаемое тело теперь включает блок `Test changes:`.
- Прогон docflow управляется установленным бинарником, а не рабочим
  деревом: при самоприменении (план docflow гонится релизом без своих
  правок) промпты прогона не содержат новых разделов. Установленные скиллы
  pi — ссылки на `~/.docflow/current/skills`, новые тексты агенты увидят
  после релиза или `docflow install-skills`.
- awk и sed Git Bash перекодируют CRLF→LF; побайтовая правка плана в тестах
  — `perl -pi` (`perlEdit` в `verify_guard_acceptance_test.go`).
- `docflow prompt` ставит юниту `[~]`: два промпта подряд в одной фикстуре
  не работают, тест откатывает файл плана между ними.

## Follow-ups
- Accepted: отказ `recordReplanChecks` (план без `## Decisions`) — путь
  недостижим через CLI: `check_replan` гоняет `lint` нового плана и
  отклоняет такой план раньше.
- Accepted: skip-маркер, разнесённый по нескольким добавленным строкам, не
  ловится — детектор построчный по решению; поведение закреплено тестом, а
  пункты — сигнал для ревью, а не замок.
- Accepted: согласованность формулировок скиллов с живым промптом review и
  acceptance не проверялась живым прогоном — формы закреплены тестами
  промптов (`testchanges_prompt_test.go`) и e2e
  `TestVerifyGuardPromptsCarryTestChanges`.
- Waits: CI на Linux и macOS после пуша — новые тесты P050 (`perl -pi`,
  PATH-заглушка claude) прогонялись только на Windows Git Bash.
