## Outcome           <!-- 2–3 строки: что теперь есть -->

Маршрут dsh передаёт модель и усилие: раннер пишет оверлей `--patch` записи
`agent-default-model` профиля dsh. dsh входит в ростер — встроенные доступы
`deepseek-account` и `deepseek-official` через канал `dsh`, модель в тройке
`dsh | deepseek-account/deepseek-v4-pro | high`. Формат не вырос.

## Decisions         <!-- решение — почему — отвергнутая альтернатива -->

- Заменяет решение «Модель и усилие маршрута — пометка, не аргумент» и
  пункт «`roster.PolicyAgents` без `dsh`» из
  [P060](P060-dsh-agent.md): флагов модели у `dsh headless` по-прежнему
  нет, но лаунчер dsh принимает `--patch <path>` — оверлей поверх профиля.
  Проверено на 0.2.2-rc.1: патч с `deepseek-v4-pro` даёт эту модель в
  системном промпте, `reasoningEffort: medium` отвергается
  `UNSUPPORTED_REASONING_EFFORT` — значение доходит до адаптера.
- Модель — `ПРОВАЙДЕР/МОДЕЛЬ`, провайдер dsh — доступ ростера, как
  `ACCESS/ID` у pi и opencode — патч заменяет `config` записи целиком, без
  `provider` профиль не собирается, а провайдер раннеру взять неоткуда —
  отвергнуты провайдер по умолчанию (у dsh это `deepseek-official`, вход
  по подписке молча ушёл бы в API-ключ) и чтение `cordis.patch.yml`
  пользователя. Голая `deepseek-flash` в тройке — ошибка раннера с
  подсказкой; без модели (`cmd` и профиль без `model`) патча нет.
- Патч — поведение декодера `stream = "dsh"`, не новый ключ профиля —
  заморозка формата; `stream` уже решает dsh-специфику вывода, живости и
  истории. `--patch` — флаг лаунчера и обязан стоять до флагов приложения
  (после `--json` dsh отвечает `unknown option '--patch'`), поэтому
  вставляется сразу после `headless`, а не через `model_args`, которые
  `BuildCommand` добавляет после прав — отвергнут перенос `--json -` в
  таблицу прав ради порядка.
- Файл патча — `dsh-model-<sha256[:4]>.yml` рядом с `schema.json` в
  каталоге логов прогона: имя от содержимого, параллельные вызовы с
  разными маршрутами не перетирают друг друга; значения — JSON-строки
  (валидный YAML без экранирования вручную).
- Доступы ростера — провайдеры dsh: `deepseek-account` (подписка
  DeepSeek, `subscription`) и `deepseek-official` (`DEEPSEEK_API_KEY`,
  `metered`) — отдельно от `deepseek` Pi: другие id моделей
  (`deepseek-flash`, `deepseek-v4-pro`) и другой провайдер в патче.
  Модели — встроенная таблица (каталог `dsh-llm-deepseek`): окно 1M,
  `max_out` 256k (потолок вывода dsh), усилия `off`/`low`/`high`/`max`,
  цена неизвестна. Проба входа — только `dsh` на PATH: проверить вход без
  генерации dsh не умеет, поэтому с CLI доступ `unknown` (маршрут идёт),
  без CLI — `not_ready` без предупреждения: таблица перечисляет доступы
  dsh на любой машине, и отсутствие dsh — обычный случай; отвергнут
  `unknown` без CLI, как у Claude, — маршрут гарантированно упал бы.

## Gotchas           <!-- ловушки, актуальные после закрытия -->

- Планы с `dsh | deepseek-flash | -` из P060 теперь падают в раннере:
  модель пишется `deepseek-account/deepseek-flash`.
- Уровни усилия DeepSeek — `off`, `low`, `high`, `max`; `medium` и
  `xhigh` dsh отвергает только при вызове модели.
- Встроенная таблица dsh держится на каталоге 0.2.2-rc.1; новая версия
  dsh может сменить id моделей.
