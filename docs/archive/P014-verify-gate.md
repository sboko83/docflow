## Outcome
Необязательный ключ `gate:` во frontmatter плана — команда, которую
`docflow verify` запускает после `Verify:` юнита. Красный gate — тот же
код 4 и та же обратная связь агенту в раннере, что и упавший `Verify`.

## Decisions
- Gate — ключ плана, а не `docs/docflow.md` — в многоприложенческом
  репозитории (RMG) планы трогают разные приложения, общий прогон всего
  репозитория на каждый юнит неподъёмен — отвергнуто: один `gate` на
  проект.
- Gate запускает `verify`, а не раннер — ручной `finish` и раннер
  проверяют одинаково, отпечаток для `done` значит «юнит и gate зелёные» —
  отвергнуто: шаг только в раннере.
- `--no-gate` для быстрых итераций отпечаток не пишет — проверка без gate
  доказывает меньше, чем нужно `done` — отвергнуто: писать отпечаток и
  с ним.
- Повод: в RMG P001 тест юнита P001.4.1 проходил в одиночку (`Verify` с
  `-only-testing`) и падал в полном наборе — общий синглтон и параллельные
  наборы Swift Testing; без полного прогона это нашлось только после
  закрытия плана.

## Gotchas
- Gate запускается на каждом `verify` без `--no-gate`: медленный набор
  умножается на число юнитов и попыток — в gate ставить самый дешёвый
  прогон, который ловит регрессии (юнит-тесты приложения), UI — в приёмку.
