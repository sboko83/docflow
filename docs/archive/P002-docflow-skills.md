## Outcome           <!-- 2–3 строки: что теперь есть -->
В `skills/` лежат все скиллы системы: `bsv-docflow-plan`, `bsv-docflow-run`,
`bsv-docflow-close` и `bsv-docs` с режимом docflow по маркеру
`docs/docflow.md`. `run` и `close` опробованы на этом репозитории
(юниты P002, закрытие P001); через Ruleblend установлен только `plan`.

## Decisions         <!-- решение — почему — отвергнутая альтернатива -->
- `verify --skip` — только когда проверку нельзя запустить в окружении, и с
  согласия пользователя — иначе агент обходит падающий `Verify` —
  отвергнуто: на усмотрение агента.
- Коммит записи без плана — `Pxxx: add note` — нужен префикс для связи
  коммита с записью — отвергнуто: произвольный subject.
- Нет `CHANGELOG.md` — шаг закрытия пропускается, файл не создаётся —
  закрытие плана не повод заводить changelog — отвергнуто: создавать по
  `bsv-changelog`.
- Закрытие плана обновляет README (док текущего состояния) — иначе README
  описывает закрытый план как идущий (всплыло на P001) — отвергнуто:
  README вне закрытия.

## Gotchas           <!-- ловушки, актуальные после закрытия -->
- `~/.claude/skills/bsv-docs/` — старая копия без режима docflow, не из
  `skills/`; `bsv-docflow-run` и `bsv-docflow-close` не установлены.
  Импорт в Ruleblend — только по явному запросу.
- `status` пишет `ready to close` у плана, где последний юнит `[~]`;
  `close` такой план не примет.
- `block` → replan → повторный `prompt` не проходит при незакоммиченной
  работе юнита: `prompt` `[ ]` → `[~]` требует чистое дерево.
- `Verify` вида `status | grep -q Pxxx` ловит id в заголовке самого юнита;
  нужен якорь.
