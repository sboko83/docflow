## Outcome
`docflow run` ведёт юниты текущего плана агентом (по умолчанию `claude -p`
по подписке) до `ready to close`: попытки с продолжением сессии, ожидание
лимита подписки, таймаут, итоги по времени и стоимости. Ассистенты и
модели задаются `agents.toml`, модель юнита — полем `Model:`. Smoke на
настоящем CLI — `tools/smoke-run.sh`.

## Decisions
- Раннер — подкоманда `docflow run` в `bin/docflow` — переиспользует разбор
  плана и выбор юнита, ставится тем же симлинком — отвергнуто: отдельный
  скрипт `bin/docflow-run` (дублирование разбора, второй файл в установке).
- Механику (`verify`, `done`, `commit`, `block`) ведёт раннер, агент только
  работает и возвращает result JSON — слабый агент путает порядок команд,
  а result JSON — единственный контракт с любым ассистентом — отвергнуто:
  агент сам гоняет цикл (раннеру пришлось бы угадывать исход по плану).
- Шаги, меняющие состояние, раннер вызывает подпроцессом своего же
  скрипта — те же проверки порядка и коды, что у человека — отвергнуто:
  прямой вызов функций в процессе.
- Адаптер ассистента — шаблон команды в TOML со встроенным профилем
  `claude`; файл пользователя накладывается по ключам — новый ассистент =
  конфиг, не код — отвергнуто: классы-адаптеры на Python; JSON-конфиг (без
  комментариев).
- Result JSON — из поля вывода (`--json-schema` у claude), иначе последний
  блок ` ```json ` — подходит ассистентам без схем.
- Модель юнита — ярус `fast|default|strong` или id в поле `Model:`, ярус
  переводит профиль; `--model` > `Model:` > профиль — ярусы держат план
  переносимым между ассистентами — отвергнуто: id вендора в плане;
  `model:` во frontmatter плана.
- Исчерпаны попытки — юнит остаётся `[~]`, код 4 или 7 — `[!]` значит
  «план устарел», а не «агент не справился» — отвергнуто: `block`.
- Лимит подписки не тратит попытку: ждать сброса и продолжить сессию —
  лимит не ошибка агента — отвергнуто: считать попыткой.
- Раннер останавливается на границе плана, закрывает человек — архивная
  запись требует суждения — отвергнуто: автозакрытие.
- Код 7 — агент не справился; замок второго раннера — код 2 — 6 занят
  `doctor`, 5 — нарушение порядка шагов юнита, а второй раннер — ошибка
  запуска — отвергнуто: код 5 для замка.
- Профиль `claude`: `--permission-mode acceptEdits --allowedTools Bash
  --permission-prompts none`, без `--bare` — в `auto` под `claude -p`
  агенту запрещалась запись файлов, `--bare` не берёт логин подписки —
  отвергнуто: `auto`; `bypassPermissions` по умолчанию.

## Gotchas
- `--allowedTools Bash` разрешает агенту любые shell-команды без вопросов.
- Вложенный `claude -p` берёт собственный OAuth-вход CLI, не вход
  десктоп-приложения; протухший вход — `is_error` и «Failed to
  authenticate», раннер тратит на него все попытки.
- `timeout = 0` в профиле — немедленный kill, а не «без таймаута»; без
  таймаута — ключа нет.
- Формат сообщения claude о лимите подписки не проверен на живом лимите:
  время сброса ищется как 10/13-значный epoch, иначе `limit_wait`.
- Раннер в корне этого репозитория возьмёт его же план; тесты и smoke —
  только во временных репозиториях.
- Пример профиля `codex` в `docs/usage.md` не проверен.

## Follow-ups
