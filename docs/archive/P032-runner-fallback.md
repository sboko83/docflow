## Outcome

`docflow run` различает отказы провайдера `limit`/`throttle`/`outage` (включая
лимит z.ai у pi) и при `limit`/`outage` переходит на следующий маршрут из
`fallback:` плана, ждёт — только когда недоступна вся цепочка; replan идёт по
той же цепочке. `timeout:` плана гасит всё дерево процессов агента, verify
агента переиспользуется при неизменном дереве, его полный лог и логи вызовов
сохраняются. Живые отказы Claude и Codex и возврат к основному после сброса не
проверены.

## Decisions

- Цепочка запасных — ключ шапки плана `fallback:` (тройки через `;`) — план
  выбирает исполнителя, dry-run проверяет маршруты
  ([P021](P021-plan-executors.md)) — отвергнут конфиг машины: режим
  исполнителей его не читает.
- Три класса отказа: `limit` (срок сброса известен или оценён), `outage`
  (5xx, 529, нет соединения, локальная модель не запущена), `throttle`
  (частота запросов) — реакции разные — отвергнут один regex `limit`.
- Признаки встроенного исполнителя проверяются до regex профиля, regex
  остаётся для legacy-конфига — иначе regex съедает throttle и outage.
- Коды z.ai по [официальной таблице](https://docs.z.ai/api-reference/api-code):
  1308/1310 → `limit`, 1302 → `throttle`, 1305 → `outage` — отвергнуто
  стороннее описание (1305 как частотный лимит).
- Время сброса z.ai без зоны — UTC+8: ранний возврат стоит одного короткого
  отказа, поздний — простоя — отвергнуты UTC и локальная зона (обе дают срок
  позже).
- Ждать — только когда недоступна вся цепочка, до ближайшего срока —
  отвергнуто ожидание основного при живых запасных.
- Ключ доступности — `agent|model`; общая подписка двух моделей выясняется
  одним быстрым отказом — отвергнут ключ по провайдеру: нет каталога моделей.
- Возврат к основному — только на границе юнита — отвергнута смена посреди
  юнита: ещё одна потеря сессии.
- Квота до юнита пропускает исполнителя только при окне ≥ 100% — отвергнут
  порог 97%: юнит часто успевает закончиться.
- replan при отказе идёт по цепочке `replan:` + `fallback:`; цикл отказов
  replan отдельный от `runUnit` — replan восстанавливает сохранённый план при
  остановке — отвергнут общий цикл: связал бы повторы юнита с откатом replan.
- Таймаут — по стене, ключ `timeout:` — отвергнут таймаут простоя:
  `xcodebuild` молчит по 13 мин.
- Kill снимает дерево по `ps` до первого сигнала и бьёт группы всех потомков —
  bash-инструмент pi запускает команды с `detached: true` — отвергнут сигнал
  только группе агента.
- Раннер переиспользует запись verify агента при совпавшем отпечатке, кроме
  `verify --skip` — та же запись, которой доверяет `done` — отвергнут
  обязательный повтор verify раннером.
- Номер лога вызова — следующий после наибольшего существующего в `run/` —
  отвергнут счётчик внутри `runUnit`: повторный `run` перезаписывал лог.

## Gotchas

- Pi 1.4.0 (`dist/core/tools/bash.js`) запускает shell с `detached: true`:
  потомки агента живут в своих группах, остановить их можно только по снимку
  `ps -A -o pid=,ppid=,pgid=`. Где `ps` запрещён (sandbox), снимок теряет
  потомков и `TestKillStopsDetachedDescendants`/приёмка падают.
- Потомок, ушедший к init до снимка (double fork), не убивается и остаётся
  жить; если он держит stdout/stderr агента, вызов ждёт их закрытия не
  дольше `agentio.PipeGrace` (5 с), вывод потомка после этого теряется.
- Циклы отказов `runUnit` и `replanUnit` раздельные: правка классов, квоты
  или ожидания в одном требует той же правки в другом.
- Ветки классификатора для Claude и Codex построены на синтетических ответах
  и документации, не на живых отказах.
- Сценарий таймаута в `internal/runner/acceptance_fallback_test.go` идёт
  ~61 с (минимум `timeout:` — 60) и требует `perl` (setsid для внука);
  без `perl` пропускается.
