title: Dev CLI runs as docflow-dev, skills switched explicitly

## Outcome
Разработка ведётся из checkout, не конфликтуя с релизом: `bash
tools/install-dev.sh` линкует `~/.local/bin/docflow-dev` → `bin/docflow`,
`docflow` на PATH остаётся установленным релизом. Личные симлинки скиллов
(`~/.zcode/skills`, `~/.agents/skills`, `~/.claude/skills`) переключает
`bash tools/switch-skills.sh [dev|release|status]`; `install-dev.sh`
скиллы больше не трогает.

## Decisions
- Дев-бинарь вызывается как `docflow-dev`, а не `docflow` — почему: линк
  `~/.local/bin/docflow` мёртв (`~/.docflow/bin` стоит в PATH раньше), а
  прежний отказ установщика «PATH указывает на релиз» блокировал
  разработку; — отвергнутая альтернатива: поднимать дев-бинарь выше релиза
  в PATH (переворачивает `docflow` во всех прочих проектах).
- Скиллы переключаются явно утилитой `tools/switch-skills.sh` — почему:
  автоматический переворот глобальных скиллов на checkout подменял текст
  скиллов в чужих сессиях; — отвергнутая альтернатива: копии скиллов в
  проекте (второй источник истины).
- «Свой» симлинк определяется по таргету (под `~/.docflow/` или под
  чекаутом), чужие (bsv-ui, ruleblend, …) не трогаются никогда; файла
  состояния нет — истина сами симлинки.

## Gotchas
- Агентские CLI сканируют скиллы при старте сессии: переключение видно
  новым сессиям, работающие продолжают со старым текстом.
- `tools/test-install.sh` проверяет контракт: после `install-dev.sh` ссылки
  остаются на релизе; `switch-skills.sh` гоняется туда-обратно на
  временно́м HOME.

## Follow-ups
- Accepted: `~/.pi/agent/skills` не входит в управляемые каталоги
  `switch-skills.sh` (там нет установленных ссылок); добавить, если
  появится.
