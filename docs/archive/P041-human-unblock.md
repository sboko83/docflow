## Outcome

`docflow unblock <id> --note "…"` снимает блок `needs human`: юнит
`[~]`, пункт Handoff `Unblocked: …`. `status` и `run` называют эту команду,
`run` в терминале спрашивает о блоке на старте; снятый юнит сначала
проверяет условие блока. Не проверены вживую консоль Windows и выполнение
правила повторной проверки настоящим агентом.

## Decisions

- Человек подтверждает шаг командой `docflow unblock`, а не ответом ждущему
  прогону — прогон часами идёт без присмотра, процесс на stdin держит
  терминал, без TTY stdin нет — отвергнуто: прогон ждёт Enter после
  human-блока.
- Прогон спрашивает о блоке только на старте, в терминале и без `--yes` —
  человек присутствует ровно когда запускает `run` — отвергнуто: вопрос
  посреди прогона; `--yes`, снимающий блок сам (безлюдный прогон не ручается
  за шаг человека).
- `unblock` всегда ставит `[~]` — работа юнита в дереве остаётся в силе, а
  промпт `[~]` дерево не проверяет — отвергнуто: `[ ]` на чистом дереве.
- Снятый юнит сначала проверяет условие блока командой; правило — только
  текст промпта в обоих циклах (CLI и runner), legacy `Blocked:` входит в
  него — заметка — заявление, а не доказательство, а условие (вход,
  устройство, доступ) в коде не проверить — отвергнуто: доверять заметке;
  автоматическая повторная проверка в раннере.
- Блоком считаются только точные формы `Blocked (human): …`,
  `Blocked (plan): …` и legacy `Blocked: …` (класс `human`); один парсер на
  `status` и `unblock` — распознавание по префиксу `Blocked` позволяло
  обычному пункту после `Blocked (plan)` скрыть плановый блок и снять его
  через `unblock` — отвергнуто: префикс; неизвестный класс как `human`.
- Ветка «условие не выполнено» в runner-тексте — ответ `blocked` с
  `blocker: "human"`, в CLI-тексте — `docflow block … --needs human` — каждый
  текст называет действие своего режима (под раннером `block` отказывает
  кодом 5) — отвергнуто: `docflow block` в runner-тексте.
- Правка текста `RunnerCycle` перепинивает хеш в `TestStrictRunnerSchema` —
  смысл пина в том, что правка промпта — осознанный шаг — отвергнуто:
  убрать сравнение хеша.
- `(needs human)` в `status` печатается только при пункте `Blocked` в
  Handoff — иначе меняется точный вывод для `[!]` без Handoff — отвергнуто:
  `(needs human)` для любого `[!]`.
- Вопрос задаётся в `Run` до подтверждения старта, а не в `runLoop` —
  watchKeys и отключение эха включаются позже — отвергнуто: вопрос в ветке
  blocked внутри `runLoop`.
- Все чтения старта идут через один `runInput` (поток + общий
  `bufio.Reader`) — второй ридер над тем же fd съедает набранную заранее
  строку — отвергнуто: отдельный ридер на каждый вопрос.
- Отмена: строка читается в горутине с `select` по контексту, `ctx.Err()`
  проверяется перед `unblock`, выход — через общий эпилог сигнала
  (128 + номер, 130) — общий `os.Stdin` закрывать нельзя, консольное чтение
  Windows не прерывается, ответ может прийти в момент отмены — отвергнуто:
  `close(os.Stdin)`; 130, зашитый в вопрос; проверка только в `select`.
- Консоль Windows определяется `syscall.GetConsoleMode` по handle
  стандартного потока — документированный признак консоли, pipe, файл и
  NUL его не проходят — отвергнуто: `golang.org/x/sys/windows`;
  `GetFileType == FILE_TYPE_CHAR` (NUL — тоже char device).
- `rootHelp` остаётся рукописным, тест сверяет имена из `docflow -h` с
  таблицей `commands` — генерация переформатировала бы закреплённый вывод,
  а сравнение вывода с самим `rootHelp` не видит пропуска (так `unblock`
  выпал из общего help) — отвергнуто: генерировать help из таблицы; второй
  рукописный список команд.

## Gotchas

- Правило повторной проверки держится на фразе «check that condition with
  a command first» в `cycleText` (`internal/cycle/commands.go`) и
  `RunnerCycle` (`internal/agents/agents.go`): тесты обоих пакетов ищут
  её; правка `RunnerCycle` требует перепина хеша в `TestStrictRunnerSchema`.
- Тексты цикла и навыков переносятся посреди фразы: ассерты по ним
  нормализуют пробелы (`strings.Fields`), иначе ломаются на переносе.
- После Ctrl-C на вопросе старта горутина чтения stdin остаётся
  заблокированной: прогон обязан завершиться сразу и этот ввод больше не
  читать.
- Общий help разбирают регуляркой `^ (\S+)` в секции `positional
  arguments:` два теста — `cmd/docflow/main_test.go` и
  `internal/runner/unblock_acceptance_test.go`; смена вёрстки help правит
  оба.
