## Outcome

Standalone-установка спрашивает один раз, ставить скиллы глобально (личные
симлинки) или только в проекты; ответ хранится в `~/.docflow/skills-mode`,
`--skills global|project` и `DOCFLOW_SKILLS` задают его явно. Не проверены
Windows-ветки (`CONIN$`, кейсы `tools/test-install.sh`) — их увидит только
CI windows-latest.

## Decisions

- Режим — одно слово в `~/.docflow/skills-mode` — каталог релиза уже
  принадлежит docflow и удаляется `uninstall` — отклонено: ключ в конфиге
  агентов (он про запуски, не про установку).
- `update` спрашивает только без сохранённого режима; `update --check`
  режим не резолвит — отклонено: спрашивать на каждом update.
- Режим, выбранный флагом или ответом, применяется к ссылкам и при
  актуальном релизе и пишется только после применения; без выбора `update`
  без нового релиза ссылки не трогает — иначе ответ `p` сохранялся без
  снятия ссылок, а сетевой отказ оставлял файл, не совпадающий со
  ссылками — отклонено: писать режим при резолюции; всегда применять
  хранимый режим на no-op.
- Project-режим сам не копирует скиллы в проекты — какие проекты на
  docflow, решает пользователь — отклонено: искать `docs/docflow.md` под
  HOME.
- Вопрос идёт в stderr, ответ читается из управляющего терминала
  (`/dev/tty`, `CONIN$`) — stdin у `curl | sh` занят скриптом — отклонено:
  stdin или stdout.
- Без терминала — `global` без записи и одна строка-подсказка; пустой
  ответ/EOF — `global`, неопознанный — вопрос повторяется; испорченный
  файл режима игнорируется — сценарные установки и CI работают как раньше —
  отклонено: ошибка.
- Тесты гасят вопрос: `tools/test-install.sh` запускает команды в новой
  сессии без терминала, на Windows закрепляет `DOCFLOW_SKILLS=global`;
  приёмочный тест идёт настоящим бинарём в PTY через `/dev/tty` —
  отклонено: подменять seam `openSkillsTTY` (путь `/dev/tty` остался бы
  непроверенным) и надеяться на отсутствие терминала (локальный прогон
  висит).

## Gotchas

- `go test ./...` не компилирует Windows-код, а `tools/test-install.sh`
  компилирует: после правок Go гонять `GOOS=windows go build ./...`.
- На Windows `CONIN$` открывается и без консоли: любой вызов
  `install`/`update` в тестах обязан нести `--skills`, `DOCFLOW_SKILLS` или
  сохранённый режим, иначе шаг CI висит на чтении.
- macOS: лидер сессии с PTY не завершается, пока master не вычитан до
  конца — тесты с PTY читают master до EOF.
- `docflow update &` в интерактивной оболочке без сохранённого режима
  получит SIGTTIN на чтении `/dev/tty`; при перенаправленном stderr вопрос
  невидим, а чтение ждёт.
- Переключение на `project` снимает ссылки только у агентов, найденных в
  PATH; ссылки ушедшего из PATH агента снимает лишь `uninstall`.
- `docflow doctor` не знает режима: в project-режиме печатает «not
  installed» по личным скиллам (код выхода 0).
