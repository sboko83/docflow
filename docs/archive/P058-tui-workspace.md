## Outcome
`docflow tui` — рабочее место проекта из четырёх экранов: «Проект» (Queue,
карточка плана, создание и правка планов, коммит служебных файлов, Backlog с
планированием через интерактивный CLI агента, параметры), «Ростер»
(доступы, условия, варианты и применение к шапке плана, скан каталога,
миграция v1), «Прогон» (поток агента с полными рассуждениями) и «История»
(прошлые прогоны с повтором потока). Маршруты берутся только из шапки
плана. Полный gate и ConPTY-сценарии прошли нативно на Windows, Linux — в
CI; исправление `tools/tui-live` для macOS подтверждается только CI.

## Decisions
- Четыре экрана на `1`–`4` вместо дерева с карточкой — ростеру, потоку и
  проекту нужна вся ширина и свои немногие клавиши, а 25 глобальных букв не
  выучить; отвергнуты новые панели и оверлеи на едином экране P052.
- Маршруты — только из шапки плана: оверлей `m` и
  `<git-dir>/docflow/tui/configuration.json` удалены, экран ростера пишет
  шапку через `roster apply` — три источника делали действующий маршрут
  неугадываемым, а шапка видна в git; отвергнут оверлей прогона рядом с
  ростером.
- Вариант ростера — пресет; созданные в TUI живут в машинных файлах:
  глобальный `roster.variants.toml` рядом с `roster.toml` и проектный
  `docs/roster.variants.toml`; пресеты `roster.toml` только читаются —
  перезапись ручного TOML теряет комментарии и порядок; отвергнуты
  round-trip-редактор `roster.toml` и проектные варианты под `<git-dir>`.
- Имя варианта уникально во всех трёх слоях, дубль — ошибка политики с
  обоими файлами — `--preset NAME` везде значит одно; отвергнут молчаливый
  приоритет проекта. Один и тот же файл в двух слоях читается один раз
  (`os.SameFile`).
- Проектный слой ищется от cwd внутри `LoadPolicy` (`format.FindRoot`), TUI
  передаёт корень явно через `LoadWorkspace(path, root)` — brief/explain/apply
  видят проектные пресеты без нового флага; отвергнут глобальный ключ
  конфигурации.
- Сохранённый вариант — разница условий и активного пресета против
  `roster.toml`, выразимая грамматикой пресета; дата, `expires`, `deny` или
  бюджет `normal` — ошибка — вариант обязан значить то, что показал экран;
  отвергнуто молчаливое отбрасывание.
- Условия правятся на копии состояния с проверкой до `State.Save`, экран
  перечитывает рабочее место после каждой удачной операции — отказ не
  оставляет полуизменённых файла и модели; отвергнуты «поменять и откатить»
  и точечное обновление строк.
- `ExplainReport` и построение разницы шапки живут в `internal/roster`, CLI и
  TUI зовут одну реализацию — TUI не импортирует `cmd`; отвергнута копия для
  экрана. `LoadPolicyState` без каталога и брифа оставлен для
  `roster off/status`, чтобы они не падали там, где работали.
- Любая запись из TUI (шапка, вариант проекта, план, `docflow.md`, коммит)
  перепроверяет живой прогон и checkout lock в момент действия, а не при
  открытии диалога — прогон может появиться между открытием и записью.
- Ростер читается фоном при первой загрузке планов, расхождение шапки с
  активным вариантом считается только для выбранной строки плана — карточка
  предупреждает до захода на «Ростер», а расчёт по всем планам читал бы
  каждый план на каждом движении курсора.
- Дельты одного сообщения сливаются в одну запись по `Activity.Message`
  (идентификатор первой дельты), лимит истории считает блоки, текст блока
  ограничен 64 KiB с дочитыванием из лога — поток рассуждений иначе вытеснял
  200 записей за секунды; отвергнуто увеличение лимита.
- Рассуждения показываются полностью и приглушённо, `t` сворачивает их до
  первой строки — выбор человека 2026-11-03; отвергнута отдельная панель.
- Повтор прошлого прогона хранится отдельно от живой истории и строится тем
  же парсером из логов вызовов — просмотр не подменяет текущий прогон.
  Сводки «Истории» читаются фоном и кэшируются в процессе по размеру и
  времени изменения журнала — сводка разбирает все логи вызовов.
- Планирование из TUI приостанавливает экран и запускает интерактивный CLI
  агента первого маршрута `heavy` с промптом про строку Backlog и скилл
  `bsv-docflow-plan`; TUI не пишет тело плана — планы пишет агент по скиллу;
  отвергнуты формы редактирования плана. Для `.cmd`/`.bat` на Windows
  переводы строк промпта заменяются пробелами, `%` и `"` — отказ с
  копируемым промптом: cmd.exe обрывает команду на переводе строки.
- `docs/usage.md` описывает клавиши каждого экрана своей таблицей — читатель
  ищет клавишу на экране, который видит; отвергнут общий список из 25 клавиш.
- Находки проверки перед закрытием исправлены напрямую юнитом P058.6.3 по
  поручению человека 2026-11-07 — отвергнуты план исправлений и перенос в
  Backlog.

## Gotchas
- Проектный слой вариантов ищется от cwd: тест, вызывающий
  `roster.LoadPolicy` из каталога пакета внутри checkout с
  `docs/roster.variants.toml`, подмешает этот слой — нужен `t.Chdir` во
  временный каталог.
- `createPlan` зовёт `os.Executable()` — из Go-теста это тестовый бинарник;
  сценарий `N` гоняется через собранный CLI. `tea.ExecProcess` требует цикла
  Bubble Tea: один вызов `Update` не доказывает запуск редактора или агента.
- ConPTY на Windows превращает введённые символы в события клавиш активной
  раскладки: символ, которого в ней нет (`$`, `@`, `#` на русской), при
  наборе теряется, а во вставке приходит как NUL. Терминальные тесты
  проверяют раскладку через `VkKeyScanW`; редактор Backlog отбрасывает
  управляющие символы вставки.
- `Output()` терминальных харнессов — текущий экран, а не журнал: notice,
  затёртый следующим нажатием, не увидеть; ждать отрисовки до повторной
  клавиши или проверять устойчивое состояние (`run:Stopping` в шапке).
- Журнал прогона закрывается `run_end` в defer после коммита юнита: чистое
  дерево ещё не значит, что «История» увидит итог прогона.
- Длинные временные пути Windows переносят имена файлов на экране; проверять
  путь по экрану без пробелов (`flatScreen`), а не по строке.
