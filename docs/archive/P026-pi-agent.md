## Outcome

pi — третий встроенный агент рядом с claude и codex: `executor: pi |
<provider/model> | <thinking>` гоняет юниты через `docflow run` (JSON
Lines, сессии, thinking); `init`, `install-skills`, `doctor` принимают
`--agent pi`. Не проверены: regex `limit` на реальном лимите z.ai и
загрузка скиллов pi из личного каталога в `docflow run`.

## Decisions

- Полный третий агент (раннер, CLI, скиллы, docs) — executor-тройка (P021)
  главный путь раннера — отклонено: только TOML-профиль.
- Setup-скилл конфигурации не делаем — выбор моделей живёт в тройке
  `executor:` или `[tiers]`, проверка — `doctor`, рецепт — usage.md —
  отклонено: скилл-опросник как второй источник истины.
- Модели не перечисляются в коде: строка из тройки уходит в `--model` как
  есть, effort — в `--thinking` — отклонено: каталог моделей.
- Квоту pi не опрашиваем — pi не отдаёт остаток подписки отдельной
  командой — отклонено: парсинг чужих эндпоинтов.
- `is_error` true, пока не было assistant `message_end`, при
  `stopReason: "error"` и при `agent_settled.aborted`; текст ошибки — из
  `errorMessage` — pi выходит с кодом 0 на ошибке API, иначе `limit` не
  видит ответ лимита и раннер падает кодом 7 вместо ожидания — отклонено:
  считать пустой поток или exit 0 успехом.
- `usage` и `cost` — суммы по всем assistant `message_end` — каждый —
  отдельный вызов API, как итог `result` у claude и `turn.completed` у
  codex — отклонено: последнее сообщение (занижало токены и стоимость
  втрое в e2e).
- `auth` — только воспроизведённая `no api key found`; `limit` — общие с
  codex строки — отклонено: выдумывать строки z.ai.
- Личная установка скиллов pi — симлинки — pi подхватывает симлинк и в
  личном, и в проектном каталоге — отклонено: копии.
- Строка версии в `doctor` — только для pi — claude и codex не менялись —
  отклонено: общая проверка версии для всех агентов.

## Gotchas

- pi 1.3.0 не отвергает неизвестную модель у известного провайдера:
  печатает Warning и уходит в API (`400 Unknown Model`). Опечатка в модели
  тройки всплывает только ошибкой агента при запуске юнита.
- В headless-режиме (`-p`) pi без project trust молча пропускает
  `.pi/skills/`: нужна запись в `~/.pi/agent/trust.json` или `--approve`.
  Личный каталог `~/.pi/agent/skills/` trust не требует.
- `totalTokens` в `usage` pi включает reasoning; входные токены —
  `input + cacheRead + cacheWrite`.
- Раннер передаёт `--session` только при повторе того же юнита; новый юнит
  всегда начинает новую сессию.
- Слово `pi` короткое: проверки текстов — `grep -w pi`, иначе ловятся
  подстроки.

## Follow-ups

- Regex `limit` для pi на реальном rate limit z.ai.
- Скиллы pi через `docflow run` после `install-skills --agent pi` в
  реальный `~/.pi/agent/skills/`.
