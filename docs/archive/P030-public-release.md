## Outcome

Дерево подготовлено к первой публикации на GitHub как 0.7.0: `var version`
поднят, `CHANGELOG.md` начат заново с одной записи 0.7.0, заметки GitHub
Release берутся из неё (`tools/release-notes.sh`), `AGENTS.md` больше не
управляется Ruleblend. Сама публикация не выполнена — в Backlog.

## Decisions

- Первая публичная версия — 0.7.0, не 0.4.0 — CLI уже в рабочем состоянии,
  до 1.0 остаётся фиксация формата; отвергнуто продолжение ряда 0.1–0.3.
- `CHANGELOG.md` начат с одной записи `[0.7.0]` — теги 0.1–0.3 не
  публикуются, ссылки на них вели бы в пустоту; запись 0.7.0 — заметки
  первого релиза и база для следующих записей; отвергнут пустой файл:
  релиз вышел бы без описания.
- Заметки GitHub Release — секция версии из `CHANGELOG.md`, нет секции —
  релиз не собирается — один источник текста, забытая запись видна сразу;
  отвергнут `gh release create` без заметок и `--generate-notes` по
  коммитам.
- После orphan-коммита основной репозиторий — GitHub: дальнейшая работа
  идёт коммитами поверх него, прежняя история остаётся приватным архивом —
  внешние PR принимаются обычным способом; отвергнуты две истории
  (приватная полная + squash-коммит на релиз): перенос PR руками.
- `AGENTS.md` — обычный файл проекта, не правило Ruleblend — источник один,
  git проекта; библиотечная копия разошлась с файлом, а маркеры `rb1`
  попали бы в публичное дерево; отвергнуто сопровождение через
  `accept_local_change`.

## Gotchas

- `uninstall` правила Ruleblend из проекта очищает и `CLAUDE.md`
  (строку `@AGENTS.md`), не только свою область в `AGENTS.md`.
