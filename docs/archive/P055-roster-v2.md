## Outcome

Ростер v2: `roster scan` собирает каталог моделей (контекст, цена,
ризонинг, усилия) из Pi/OpenCode и встроенных метаданных Codex/Claude,
`--online` добавляет models.dev; стабильная политика `roster.toml` и
временные условия `roster.state.toml` (`off/on/budget/expire/allow/deny`,
`--preset`) резолвятся `roster brief` в цепочки ролей, бюджет чтения
юнита и объяснение, `roster apply` пишет шапку плана. v1-формат читает
только `roster migrate`; любой другой командный путь даёт на v1-файле
код 2 с подсказкой. Формат плана не меняется (`docflow: 3`), раннер
ростер не читает.

## Decisions

- Доступ — единица квоты и независимости, а не провайдер: одна подписка
  `opencode-go` — один доступ, даже если к ней ходят `pi` и `opencode`
  (агенты доступа объединяются); fallback повторяет доступ, а не
  `agent|model`, — иначе две попытки на одну квоту.
- Три файла разделены: `roster.toml` — стабильные доступы, allowlist,
  доверие, пресеты; `roster.state.toml` — временные условия и expiry;
  `catalog.json` — найденные модели. Условия не переписывают ростер;
  state с именем, которого нет в политике, — код 2, а не тихий пропуск.
- Резолвинг — только при планировании: план хранит конкретные маршруты,
  раннер ростер не читает. Временное исключение применяется новым планом
  или явным `roster apply` — отвергнут roster-aware `run`, ломающий
  воспроизводимость прогона.
- Бюджет доступа — лестница `prefer > normal > lean > minimal > off`:
  `minimal` — только `acceptance`/`replan`, `lean` — без `heavy`,
  `acceptance`, `replan`, `off` — ничего; покрывает «codex по минимуму» —
  отвергнут числовой share.
- Класс модели (`cheap|standard|strong`) — автоматика по семейству
  (`flash/mini/lite → cheap`, `pro/sol/opus → strong`) плюс `[model]`;
  класс — сильнейший тир её маршрутов, а пин `[effort]` по
  `ACCESS/MODEL` перекрывает лестницу классов и несёт единственное
  усилие маршрута; «без усилия» мигрирует как `-`.
- Бюджет чтения юнита — рекомендация брифа:
  `(context − max_out − резерв) × доля роли × множитель класса
  (0.75/1.0/1.25)`, зажат в 20k..250k; judge-роли получают только
  `diff/test`-scope. Это не ключ плана и не проверка `lint`; неизвестный
  контекст даёт цель 0 и `context unknown`, неизвестный max_out
  считается нулём с пометкой в `why`.
- `check`/`trusted` — свойства доступа: `check` исключает
  review/acceptance/replan; `trusted` = доверенный доступ плюс модель
  класса strong; нет независимого ревьюера — ошибка политики с
  подсказками, один маршрут — предупреждение `no fallback`. Self-review
  отвергнут.
- Русские условия переводит скилл планирования по таблице «фраза →
  флаг»; CLI не парсит текст. Разовые флаги (`--off/--minimal/--only`,
  `--preset`) — один in-memory overlay, общий для brief/explain/apply, и
  никогда не пишутся в state.
- Живые квоты не опрашиваются: планирование опирается на auth, expiry и
  условия; квоту на старте прогона по-прежнему проверяет раннер —
  отвергнут второй источник правды о квоте.
- Порядок резолва — у одного владельца: резолвер фильтрует по ролям
  (off/expiry/auth/budget/class/allowlist/check/trusted), сортирует
  кандидатов (`prefer > normal > lean`, `minimal` в конце) и пишет
  причины в Skipped; построитель цепочек только убирает повтор доступа;
  фильтры ролей не дублируются. Предупреждения — строки, фильтруемые по
  суффиксу ` for <role>`.
- Пустая цепочка роли — предупреждение, не ошибка (резолвер не знает
  ролей плана); но `apply` отказывает кодом 2 без записи, если открытому
  юниту без явного `Executor:` не хватает цепочки его роли; закрытые
  юниты и явные `Executor:` exempt.
- Выбор модели: минимальный подходящий класс, затем цена (неизвестная —
  после известной, nil-цена не бесплатна), затем больший контекст, затем
  id. Текст маршрута в плане — `ACCESS/ID` для pi/opencode и голый id
  для codex/claude.
- Строки матрицы review — только check-доступы, реально дающие маршрут;
  шапка плана пишется только из `Brief.Header()`, explain сравнивает
  объединение ключей шапки и фильтрует предупреждения по ролям плана
  (executor+replan всегда, остальные — из `Role:` юнитов).
- Миграция v1 → v2 односторонняя: `Migrate` конвертирует провайдера
  `pi` с моделью `X/Y` в доступ `X` с каналом `pi` (одна квота),
  сохраняет усилия пинами `[effort]`, тир маршрутов даёт класс модели,
  spend профиля — order пресета плюс off для неименованных доступов,
  отличающиеся флаги провайдера — комментарий в пресете; сгенерированный
  текст перечитывается ParsePolicy, `--write` оставляет `.bak`.
- После cutover v1-парсер живёт только в `legacy.go` для migrate; любой
  другой путь на v1-файле — код 2 с подсказкой migrate; `--profile`
  разобран только ради ошибки, называющей `--preset`.
- Кэш каталога расходный: незнакомая version равна отсутствию кэша;
  запись атомарна через временный файл и rename; путь всегда
  `$XDG_CACHE_HOME/docflow/...` или `~/.cache/...` (и на macOS, не
  `~/Library/Caches`). `models`/`status` кэш только читают: пустой кэш —
  код 0 с подсказкой, неизвестный доступ — код 2, неизвестные значения —
  `unknown`, не ноль.
- Скан вызывает CLI только через `agentio.CallAgent` (таймаут 30s),
  сортирует каталог сам и не читает auth-файлы и headers (org id);
  слияние источников — «пустое не затирает непустое», `reasoning=false`
  не сбрасывает `true`, cost — указатель, провенанс каждого поля в
  Provenance; ошибка источника — предупреждение, тело ответа в текст не
  попадает.
- Auth — один статус на доступ (ready/not_ready/unknown), готовый канал
  побеждает; Claude без конфига и CLI — unknown, не отказ.
- Обогащение models.dev — опциональное и только заполняет пустые поля
  (store и метаданные CLI точнее); доступ→провайдер — явная карта;
  контекст Codex берётся из окна самого CLI (500k), а не из API-окна
  models.dev (1.05M); кэш models.dev хранит исходный документ с TTL.
- Семантика state: `models` заменяет allowlist политики, `exclude`
  расширяет его (условие сужает, но не расширяет), отказы суммируются;
  off/expires дата включительная, истёкший off снимается в памяти;
  `on` снимает только off/until/budget-off; условия пресета
  взаимоисключающи, `minimal` требует trusted и на уровне пресета.
- Политика валидируется при загрузке: ссылки `[model]`/`[effort]`/
  пресетов обязаны называть объявленный доступ; пустой allowlist условия
  — «ни одной модели», отсутствие ключа — «все»; в имени доступа
  запрещены пробел, `/`, `|`, `,`, `=`.
- Бенчмарк возит коммитируемый `bench/catalog.json` через
  XDG_CACHE_HOME — маршруты прогона воспроизводимы на CI без личного
  скана; chains v2 сознательно отличаются от v1 (сортировка по бюджету,
  пин усилия), изменение записано в docs/design/bench.md без
  перезапуска результатов.
- Read:-прокси предупреждения apply считается только по `Read:`-ссылкам
  (/4), без Context и промпта — бюджет роли это рекомендация чтения.
  Предупреждения apply идут с префиксом `docflow: roster:`, lint-вербик
  не фильтруется, JSON apply сохраняет код выхода.
- Примеры политики в docs проверяются тестом: извлечение блоков и резолв
  на фикстурном каталоге с фиксированным днём — пример не ломается
  незаметно.

## Gotchas

- Тексты предупреждений живут в `resolve_chain.go`, а бриф/apply/explain
  фильтруют их по суффиксу ` for <role>` — сменив текст, обнови
  сопоставление ролей, иначе фильтр молча перестанет работать.
- Golden `internal/roster/testdata/brief-scenario.txt` пришпилен к дню
  2026-06-01: zai истекает 2026-06-30, после этой даты живой бриф по той
  же политике закономерно даёт другие цепочки.
- Фикстуры бенчмарка ходят парами: `bench/roster.toml` +
  `bench/catalog.json` (каталог кладётся в XDG_CACHE_HOME арма); локальный
  `bench/roster.state.toml` меняет chains бенчмарка — не держать его в
  репозитории.
- Ноль в каталоге значит «неизвестно»: `Context == 0` и `MaxOut == 0` —
  unknown, `Cost == nil` — цена неизвестна; модель с неизвестным
  контекстом не попадает в heavy.
- `roster migrate` односторонний: v2-файл отказывает в повторной
  миграции, v1-текст сохраняется в `roster.toml.bak`.
- `no fallback for <role>` печатается и apply, и lint — дубль принят.
- `DefaultCachePath` всегда `~/.cache` даже на macOS (не
  `~/Library/Caches`) — сделано намеренно, единый путь со скриптами CI.
