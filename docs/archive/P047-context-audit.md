## Outcome

Контекст сессии измерен и ограничен: `tools/context-audit.py` печатает
каждый вход docflow (старт-читы, скиллы, design-топики с их архивными
Gotchas, промпт юнита) сейчас / на план / при 200 планах и валится по
бюджетам (`--check`); `tools/read-audit.py` показывает чтения агента за
пределами `Read:` юнита по транскриптам; `lint` предупреждает о целом
`Read:` большого файла (`whole_read_limit`, runner.md разбит на секции).
На этом репозитории все бюджеты в норме; лишние чтения — ~42% токенов
юнита.

## Decisions

- Стоимость юнита ограничивается сужением ссылок (диапазон, `#anchor`),
  а не капом Gotchas — прочитанный диапазон сам решает, ловушки каких
  записей наследуются — отвергнуто: фиксированный кап на
  `## Archive gotchas` (рвёт ловушки случайно).
- Целый файл сверх `whole_read_limit` (необязательный ключ
  `docs/docflow.md`, по умолчанию 4000) в `Read:` открытого юнита или в
  `## Context` плана с открытым юнитом — предупреждение `lint` — целые
  ссылки закрытых планов и маленьких проектов остаются валидными —
  отвергнуто: ошибка (ломает открытые планы при апгрейде).
- Средний рост на план считается по окну после squash (базовая точка —
  родитель коммита закрытия P035, флаг `--window-plan`) — вся история до
  публичного релиза сжата в один коммит — отвергнуто: средняя по всем
  46 планам (занижает рост вчетверо).
- Рост prompt-строк моделируется из источников: прирост Gotchas
  связанных записей плюс средний размер Gotchas × новые связи × доля
  ссылок, сохраняемая диапазонами — fixture-плана нет внутри git-окна —
  отвергнуто: эмпирика по историческим юнитам и фиксированный нулевой
  рост (дешёвый промпт навсегда дешёвый, ловушку не видно).
- Чтения мерятся на коммите юнита (нет своего — на коммите закрытия
  плана, рабочий юнит — по дереву), пути разрешаются по списку файлов
  этого коммита (tree_paths), затем по диску — размер соответствует
  эпохе, файл, удалённый позже, остаётся чтением — отвергнуто: всё по
  рабочему дереву (одно чтение 190MB Go-бинаря дало 47M токенов,
  исторические пути терялись).
- Размер одного чтения ограничен выходным лимитом инструмента
  (50 KB / 2000 строк), лимит делится между файлами одной команды —
  больше инструмента до агента не доходит — отвергнуто: размер файла
  целиком (`head -1` 200MB лога стоил 50M токенов).
- Коммит юнита ищется по `git log --all`; юнит без файла плана в истории
  помечается `unmeasured` и из агрегата исключён — отвергнуто: поиск по
  HEAD (ранние планы после squash теряются, все их чтения становятся
  лишними) и подсчёт unmeasured лишними (артефакт squash, не привычка
  агента).
- Shell-глобы раскрываются и по дереву коммита, и по диску,
  сопоставление посимвольно по компонентам пути (fnmatchcase) — shell
  `*` не пересекает `/` — отвергнуто: глоб только по диску и плоский
  fnmatch (`docs/*` именует docs/a/b.md).
- Строка бюджета в `--check` падает по проекции, а по текущему размеру —
  когда тот уже выше лимита — убывающая проекция не прячет
  существующий пробой — отвергнуто: сверять только текущий размер
  (прячет будущий перерасход) и только проекцию (прячет текущий пробой —
  дефект ревью P047.1.4).
- Регрессии аудитов живут в `tools/test-context-audits.py` вне gate и
  parity — их запускает Verify приёмки — отвергнуто: python-сценарии в
  `go test ./...` (инструменты не являются CLI).
- read-audit включает все юниты из `docflow stats` и pi-логов; юнит без
  читаемых вызовов инструментов попадает в `skipped` — отчёт честно
  показывает долю неизмеренных — отвергнуто: фильтр `source=transcript`
  (юниты Codex и `claude -p` выпадали молча).
- Context-предупреждение о целом файле — только у планов с открытым
  юнитом: Context кормит промпты лишь открытых юнитов — отвергнуто:
  предупреждать Context всех планов (шум по закрытой истории).

## Gotchas

- `ArchiveGotchas` тянет Gotchas всех записей, на которые ссылается файл
  целиком; диапазон `path:L10-80` или `path#anchor` наследует ловушки
  только записей внутри него. Целый `Read:` на большой topic-файл дороже
  диапазона на порядок: runner.md — ~14k токенов файла плюс ~5k токенов
  Gotchas от 22 записей.
- Окно роста проекции задаётся флагом `--window-plan` (по умолчанию
  P035). После нового squash базовая точка окна теряется — лечится
  флагом, без правки кода.
- Строка start-reads держится у лимита 4000 с запасом ~50 токенов
  проекции, README растёт ~10 токенов на закрытый план: правящие README
  юниты проверяют `python3 tools/context-audit.py --check`.
- `docflow finish` делает `git add -A`, а `tools/__pycache__` (остаётся
  от импорта tools/*.py) в .gitignore не входит — удалять каталог перед
  finish.
- Коммиты юнитов до публичного релиза недостижимы из HEAD (squash):
  git-обвязка по ранним планам работает только с `git log --all`.
- `docflow prompt` требует git-репозиторий и для `[ ]` чистое дерево:
  временные копии для аудита делают `git init` без коммита, а юниты
  копии записывают как `[~]`.

## Follow-ups

- Accepted: точность линейной проекции — сигнал тренда по окну после
  squash; контрольная точка появится с закрытием следующего плана
  (сравнить предсказание at(N+1) с фактическим размером runner.md и его
  Gotchas).
- Accepted: переносимость git-обвязки и матчера путей на Linux/Windows —
  инструменты dev-only, их запускает мейнтейнер на macOS-checkout, в
  релизный бинарь и пользовательский путь они не входят.
- Accepted: транскрипт P011.1.1 недоступен — чтение исторического файла
  закреплено синтетическими регрессиями (HistoricalReadTest) и реальным
  блобом на коммите (RealHistoryP011Test).
- Accepted: now-ветка строки prompt:regular:ranged без отдельной
  фикстуры — now-проверка едина для всех строк бюджета (общий цикл в
  `--check`), покрыта тестом по start-reads.
- Accepted: `fixture_repo` в context-audit.py оставляет временный
  каталог при исключении между mkdtemp и rmtree — процесс завершается
  диагностикой, каталог убирает OS.
- Прогон `tools/test-context-audits.py` в CI (ubuntu-latest,
  windows-latest/Git Bash) — перенесено в Backlog.
- read-audit: флаги `grep -l/-c/-q` ограничивают вывод именами или
  счётчиком, а размер считается как полный текст — команды по многим
  файлам завышают лишние токены — перенесено в Backlog.
