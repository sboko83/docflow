## Outcome

Добавлена холодная проверка скилла планирования; живые тестовые и демо-скрипты
используют Pi/GLM Flash и Codex. Аудит сохранённых прогонов оставил
неподтверждённой эскалацию Codex: дальнейшие проверки вынесены в Backlog.

## Decisions

- Планы с изменением UI, CLI или API всегда заканчиваются acceptance,
  включая план с одним обычным юнитом — холодный агент пропускал приёмку
  малой CLI-задачи; отвергнуто ослабление проверки вместо уточнения скилла.
- Живые тесты и demo используют Pi/GLM Flash и Codex — лимит Claude нужен
  для рабочей нагрузки; его офлайн-заглушки сохраняют проверку адаптера
  и установки. Отвергнута возможность выбрать Claude в живых скриптах.
  Разделение исполнителей юнитов самого P039 принято в
  [P043](P043-local-worker.md).
- Маршруты холодного тестового плана сверяются со снимком запрошенного
  default-профиля — повторная проверка воспроизводима. Отвергнута сверка
  рабочих планов с текущим ростером: назначения согласуются в самом плане
  и могут быть заданы вручную.
- `--check-only` переиспользует результат успешного вызова без модели,
  сборки и создания фикстуры — повторные проверки не расходуют подписку.
  Ненулевой выход и таймаут исключают успех даже при наличии плана;
  watchdog завершает и дожидается таймера, чтобы тот не удерживал stdout.
  Отвергнуто принятие результата только по наличию корректного плана.
- Для аудита общего механизма эскалации выбраны сохранённые Xcode-прогоны
  RMG — отдельный Gradle-прогон отвергнут как дублирующий проверку записи
  вне репозитория. Свидетельство — отказ песочницы и успешный повтор той же
  команды: поток не содержит approval-событий; самоотчёт агента отвергнут.
- Спиннер проверяется реальным декодером раннера — копия декодера на Python
  могла бы скрыть расхождение с рабочим путём. Содержимое логов RMG остаётся
  вне репозитория; отвергнуты цитаты приватных команд и сообщений.

## Gotchas

- Полный холодный прогон расходует подписку выбранной модели и остаётся
  вне CI и гейта. `--check-only` требует артефакты успешного полного вызова
  в TMPDIR; после их удаления нужен новый полный прогон. Его результат
  относится к выбранной модели в Pi, автоматической смены провайдера нет.
- Сохранённые логи RMG получены старым Python-раннером. Они не содержат
  нужных отказов записи в DerivedData/кэши и отказов внутри resumed-вызовов;
  происхождение запроса эскалации Verify для P008.2.2 из них не восстановить.
- Активность спиннера появляется при инструментальных событиях; сообщение
  агента без инструментальных вызовов даёт пустую активность.

## Follow-ups
