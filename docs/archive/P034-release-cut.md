## Outcome

Релиз режет `tools/cut-release.sh` в два шага: `prepare BUMP` — локально
(гейты, bump версии, перенос `[Unreleased]`, коммит, тег), `publish` —
push main, ожидание CI, push тега, ожидание workflow релиза и проверка
ассетов. `release.yml` после публикации ставит релиз через `curl … | sh`
и запускает его. `prepare` проверен на временном клоне; `publish` и job
`smoke` вживую не прогонялись — в Follow-ups.

## Decisions

- Два шага, push только в `publish` — push и тег необратимы, пауза между
  шагами — момент просмотреть релизный коммит; отвергнут один шаг с
  автопушем.
- Номер версии задаёт человек (`patch|minor|major|X.Y.Z`), без аргумента
  скрипт только подсказывает по секциям `[Unreleased]` — до 1.0 ломающее
  изменение идёт в minor, это суждение, не правило; отвергнуто
  автоматическое вычисление.
- Тег пушится только после зелёного CI на релизном коммите — push тега
  публикует релиз, красный main не должен им стать; отвергнут
  одновременный push main и тега.
- `prepare` отказывает при плане со `status: active` — тег ставится после
  закрытия плана; отвергнут релиз посреди плана.
- `tools/audit-public.sh` — гейт `prepare`, исключения скрипт не добавляет —
  каждое разрешение в `audit-public.allow` ревьюит человек.
- Публикация только в `origin` (GitHub) — второй remote хранит прежнюю
  приватную историю, его main не предок текущего.
- Job `smoke` ставит опубликованный релиз через `install.sh` на linux
  amd64, linux arm64 и macOS и проверяет `--version`, `update --check`,
  `init` и `status` — проверяется то, что получит пользователь; отвергнута
  только локальная раскладка `tools/test-install.sh`: она не ловит
  ошибки публикации (ассеты, `latest`, raw `install.sh`).

## Gotchas

- `prepare` идёт около 3 минут: в гейтах `tools/test-install.sh`.
- `publish` повторяем: шаги, уже сделанные на remote (push main, push
  тега), пропускаются. Если `latest/download/VERSION` ещё отдаёт прежнюю
  версию, достаточно повторить `publish`.
- `publish` требует `gh` с доступом к `sboko83/docflow`; repo берётся из
  URL `origin`, а не из выбора `gh` по умолчанию: remote два.
- `ci.yml` срабатывает и на push тега; `publish` ждёт последний run
  `ci.yml` для коммита, повторный запуск после push тега ждёт уже его.

## Follow-ups

- Первый живой `publish` и job `smoke` (в том числе `ubuntu-24.04-arm`)
  — на следующем релизе.
