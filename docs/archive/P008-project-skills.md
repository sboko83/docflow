## Outcome
`docflow install-skills --project` и `docflow init --skills` копируют
`skills/*` в `.claude/skills/` проекта для облачных сессий; `doctor`
сверяет эти копии и подсказывает обновление.

## Decisions
- Копии в проекте, а не загрузка скиллов в аккаунт claude.ai — копия
  привязана к проекту и версионируется с ним — скиллы аккаунта общие для
  всех проектов и без версии.
- Флаг `--skills`, а не интерактивный вопрос в `init` — `init` запускают и
  агенты без TTY — отвергнут вопрос при наличии TTY: два поведения одной
  команды.
- Обновление копий — `install-skills --project`, не повторный
  `init --skills` — `init` отказывает при существующем `docs/docflow.md`,
  ослаблять это — размывать команду.
- Каталог назначения — копия docflow, если это не симлинк и `name:` его
  `SKILL.md` равен `name:` исходного скилла; такой заменяется целиком.
  Всё остальное по этому пути — чужое: отказ, ничего не записано —
  отвергнут файл-маркер в копии: ломает побайтное сравнение с `skills/`.
- docflow не распознаёт проектные цели Ruleblend — один установщик на
  проект, правило в docs/design/ — распознавание требует знать внутренности
  Ruleblend.

## Gotchas
- Локально личный скилл (`~/.claude/skills`) перекрывает проектный с тем
  же именем: проектная копия действует только в облачной сессии.
- Правка внутри проектной копии стирается следующим
  `install-skills --project`: исходники — только `skills/` этого
  репозитория.
