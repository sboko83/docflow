## Outcome

Docflow поддерживает Windows 10/11 с Git for Windows: команды плана,
раннер Claude/Codex, релизная установка, обновление и удаление. CI включает
Windows. Не проверены Linux/macOS после изменений, Unix fixtures на Windows
и установка при отключённом Developer Mode; продолжение — в Follow-ups.

## Decisions

- Команды плана на Windows выполняет Git Bash; без него остаётся
  `%COMSPEC% /c` — планы пишутся в POSIX sh на любой ОС — отвергнут
  `cmd.exe` как единственная оболочка. Корень Git ищется на один-два уровня
  выше `git.exe`, включая раскладку `mingw64/bin`; WSL Bash не используется.
- `current` и личные ссылки скиллов на Windows — directory junction,
  пользовательский `Path` ведёт в `current` — не нужны привилегии и замена
  запущенного exe — отвергнуты симлинки, требующие Developer Mode,
  и копия бинарника в `bin/`.
- `install.sh` в Git Bash остаётся общим установщиком, архивы — `.tar.gz`
  для amd64 и arm64 — Git Bash уже нужен, распаковщик общий — отвергнуты
  отдельный `install.ps1` и Windows-архивы `.zip`.
- Дерево процессов завершается через `taskkill /T /F /PID`, при ошибке —
  только процесс агента через `Process.Kill` — стандартная библиотека без
  загрузки DLL — отвергнуты Job Objects через `syscall`.
- При удалении запущенный exe переносится в соседний временный каталог,
  затем скрытый PowerShell удаляет его после выхода — перенос остаётся
  на том же томе, установка исчезает синхронно — отвергнуто отложенное
  удаление всей установки без подтверждения результата в CLI.
- E2E-харнесс сохраняет имя и раскладку и сравнивает бинарник с собой —
  Python-версия удалена, сценарии остаются проверкой CLI целиком — отвергнуто
  удаление харнесса. Восстановление сценариев перенесено из P039 сюда,
  чтобы Windows-приёмка не зависела от незавершённого плана на другой машине.
- На Windows харнесс задаёт `MSYS=winsymlinks:nativestrict` — Git Bash иначе
  может молча скопировать файл вместо ссылки — отвергнут пропуск сценариев
  `install-dev` и маскировка причины поздней ошибкой поиска скиллов.

## Gotchas

- В изолированных тестах Windows нужны одновременно `HOME` и
  `USERPROFILE`: `os.UserHomeDir` читает вторую переменную. `TMP` и `TEMP`
  тоже направляются в песочницу, иначе Go может выбрать системный каталог.
- Fake-агенты без расширения не находятся через `exec.LookPath` на Windows:
  рядом нужен `.cmd`-шим. E2E запускается без реальных агентов в `PATH`,
  чтобы ошибка фикстуры не расходовала подписку. MSYS-инструментам при
  копировании в изолированный `PATH` нужны их DLL.
- Для junction используется `dirlink.Resolve`: Go сообщает `ModeIrregular`,
  а `filepath.EvalSymlinks` может оставить путь неразрешённым. Заблокированная
  старая версия удаляется при следующем обновлении после выхода процесса.
- `DOCFLOW_TEST_USER_PATH` должен указывать на существующий абсолютный
  обычный файл: неверное значение завершает проверку ошибкой, без перехода
  к настоящему реестру пользователя.
- `tools/install-dev.sh` и его e2e создают файловые симлинки; в отличие от
  релизной установки им нужны Developer Mode или повышенные права.
- Профиль оболочки агента может заменить унаследованный `PATH`; smoke-план
  передаёт абсолютный путь к checkout-бинарнику. В parity нормализуются
  длительности юнитов, перепланирования и всего прогона.

## Follow-ups

- Проверить Go-тесты и e2e на Linux и macOS после Windows-изменений;
  результаты CI доступны после push, локальная приёмка была на Windows.
- Перенести Unix shell fixtures пакетов `internal/runner` и
  `internal/agentio` на Windows: пока эти тесты там пропускаются.
- Проверить релизную установку, обновление, ссылки скиллов и удаление
  на Windows с отключённым Developer Mode и без прав администратора.
