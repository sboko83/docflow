## Outcome
`docflow run` выбирает ассистента, модель и усилие на каждый юнит по ярусу
`fast|default|strong|max` из `[tiers]` конфига: Claude Code и Codex CLI
идут в одном прогоне. После каждого юнита, в том числе упавшего или
прерванного, печатается строка `quota:` с дельтой по агенту. На реальной
подписке Codex (окна 5h/7d, реальный лимит) не проверено: аккаунт пока
free, одно окно 30d.

## Decisions
- Маршрут яруса — одна верхняя таблица `[tiers.<ярус>]` (`agent`, `model`,
  `effort`) вместо `models` у профиля и `default_agent` — таблица
  ярус → модель внутри профиля не отправит два яруса двум ассистентам;
  старые ключи дают код 2 с подсказкой — отвергнуто: `models` плюс отдельная
  таблица ярус → ассистент (две таблицы держать согласованными).
- Четыре стандартных яруса, `max` — для самых тяжёлых юнитов — нужен
  отдельный выбор модели под них — отвергнуто: произвольные имена ярусов
  (`lint` не знает чужой конфиг, план перестаёт быть переносимым).
- Не-ярус в `--model` — id модели на ярусе `default` и целиком перекрывает
  `Model:` юнита — один приоритет без смеси — отвергнуто: ярус из `Model:`,
  id из `--model`.
- Codex — `--approve-for-me`, сеть включена, подсказка об эскалации в
  `instructions` — ближе всего к `auto` у Claude: песочница по умолчанию,
  запись вне репозитория (`~/.gradle`, DerivedData) идёт через
  автоматический ревьюер; проверено вызовом — отвергнуто:
  `--dangerously-bypass-approvals-and-sandbox` (без проверки),
  workspace-write без ревьюера (Gradle и Xcode падают).
- Одна strict `RESULT_SCHEMA` (все ключи обязательны, пустые значения
  допустимы) для всех ассистентов — Codex отвергает необязательные ключи,
  Claude принимает обе — отвергнуто: схема на профиль.
- Продолжение Codex — `resume_args = ["resume", "{session}"]` в конце argv —
  опции `exec` перед подкомандой действуют, stdin читается — отвергнуто:
  отдельный ключ `resume_cmd`.
- Флаг ошибки при коде 0 — неудачная попытка — Codex сообщает `turn.failed`
  в потоке, а выходит с 0 — отвергнуто: полагаться на код выхода.
- Время сброса лимита из данных (rollout Codex, `status: rejected` Claude)
  приоритетнее regex и само признак лимита, но только у упавшего вызова —
  успешный ответ может процитировать событие лимита — отвергнуто: regex
  как единственный признак.
- Квота юнита печатается из одного `finally` вокруг `_run_unit`, маршрут
  считается до него — так покрыты все выходы, включая сигнал — отвергнуто:
  печать на каждом `return`.
- Переписывание на Rust или Go не сейчас — старт 0.09 с против минут
  вызова агента; Windows требует нового кода групп процессов и сигналов на
  любом языке; тесты грузят модуль в процесс и переписываются тоже —
  отвергнуто: порт до поддержки Codex. Вернуться, когда понадобится Windows
  или раздача другим людям.

## Gotchas
- Квоты Codex нет в stdout `codex exec --json`: она только в rollout-файле
  `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-*-<thread_id>.jsonl`; `resume`
  дописывает тот же файл. Нет файла — нет квоты, без ошибки.
- `input_tokens` Codex уже включает `cached_input_tokens`: складывать их —
  двойной счёт.
- Codex эскалирует команду, только если промпт это велит: без подсказки в
  `instructions` запись вне репозитория молча падает в песочнице.
- `codex exec resume --help` не показывает `--approve-for-me`; эскалация
  после `resume` проверена на машине, где `~/.codex/config.toml` задаёт
  `approvals_reviewer = "auto_review"`, — без него не проверено.
- Первая дельта квоты Codex в прогоне всегда `+0`: стартовое значение
  берётся после первого вызова, до него квоту узнать неоткуда.

## Follow-ups
- С платной подпиской Codex: окна 5h/7d в строке `quota:`, реальный лимит
  (текст ошибки, `limit_reset` по rollout с `used_percent` 100).
- Реальный юнит на Codex с Gradle или Xcode: эскалация записи вне
  репозитория, активность в спиннере из живого потока, `--approve-for-me`
  после `resume` без `approvals_reviewer` в конфиге Codex.
- Квота, пришедшая в потоке прерванного (Ctrl-C) вызова, в строке
  `quota:` юнита — не покрыта тестом.
