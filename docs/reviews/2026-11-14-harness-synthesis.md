# Харнес, супервизор, канал: сводная позиция — 2026-11-14

Статус: записка для решения. Ничего не принято, код и формат не менялись.
Сводит пять записок от 12–13 ноября и пересматривает их под текущие
ограничения:

- [runner против walker](2026-11-12-runner-vs-harness.md);
- [внешний харнес](2026-11-12-external-harness.md);
- [харнес и пульт](2026-11-13-harness-control-plane.md);

## Ограничения на 2026-11-14

Цель: большой план выполняется автономно, человек получает пуш только
когда нужно его решение, и отвечает с телефона.

- Claude Code сейчас недоступен.
- У ZCode нет пушей.
- У OpenCode нет мобильного приложения.
- Есть Apple-аккаунт разработчика и свой VPS: можно написать приложение и
  слать пуши самому.

## С чем согласны все пять записок

1. Формат плана, `Read:`, Handoff, `verify → done → commit`, ростер —
   ценность; их не трогаем.
2. Свежий контекст на юнит обязателен. Одна длинная сессия на весь план —
   регресс.
3. Смена харнеса решает канал, но не частоту стопов. Стопы — свойство
   политики раннера.
4. Самое слабое место — лимит у координатора: модель без квоты не может
   решить, кем себя заменить. Ни одна записка это не решила.

## Где записки расходятся

- **Walker вместо раннера** ([runner против walker](2026-11-12-runner-vs-harness.md)).
  Неверна посылка «guard'ы существуют только из-за отсутствия канала».
  Они появились после реальных зацикливаний: в P052 юнит ревью
  блокировался 10 раз и породил 19 юнитов исправлений. С каналом они
  нужны так же; меняется только то, что вместо стопа они зовут того, кто
  решает.
- **T3 Code / HAPI / Happy** ([внешний харнес](2026-11-12-external-harness.md)).
  Сторонний relay и ещё один продукт в цепочке, а лимит координатора не
  решён. Под текущие ограничения выигрыша нет.
- **Дирижёр в Claude Code** ([дирижёр поверх run](2026-11-13-supervisor-harness.md)).
  Claude Code недоступен; к тому же долгоживущая сессия возвращает риск
  лимита у координатора.
- **`docflow serve` + SSE + Telegram** ([харнес и пульт](2026-11-13-harness-control-plane.md)).
  Направление верное, но для первого шага больше, чем нужно: сервер и
  поток событий нужны своему приложению, а не боту.

Самая сильная идея пяти записок прошла как запасной вариант —
[безголовый режим](2026-11-13-supervisor-prompt.md#что-требуется-от-харнесса)
дирижёра.

## Позиция: внешний харнес не нужен

Три части, две из которых уже есть.

### 1. Двигатель — `docflow run` без изменений

Квоты, fallback, ожидание сброса, `verify`/`commit`, replan остаются
детерминированными и покрытыми тестами.

### 2. Супервизор — разовый вызов на стоп, а не сессия

```
петля (скрипт)
  ├─ docflow run --yes
  ├─ код 0 / ready to close → docflow run --close, пуш «готово»
  ├─ код 3/4/7 → разовый агент: мандат + описание стопа
  │     ├─ «разобрался» → запись Supervisor: в Decisions, снова run
  │     └─ «вопрос + варианты» → пуш с кнопками, ждать ответа,
  │           второй разовый вызов: стоп + ответ → снова run
  └─ квоты нет ни у одного супервизора → пуш «жду сброса до X», спать
```

Агент — `codex exec`, `opencode run` или другой из ростера; он разбирает
один стоп и завершается.

- Контекст координатора не растёт: состояния у него нет, всё в
  репозитории.
- **Лимит координатора решён:** кончилась квота у супервизора — петля
  берёт следующего из ростера; кончилась у всех — пуш и ожидание. Живёт
  детерминированная петля, а не модель.
- Мандат, таблица решений, жёсткие запреты и формат вопроса уже написаны
  в [промпте дирижёра](2026-11-13-supervisor-prompt.md#промпт); их нужно
  переложить на разовые вызовы с JSON-ответом.

Защиты раннера не снимаются: супервизор принимает решения, которые сейчас
ждут человека, в пределах мандата и с записью в `## Decisions`. Главный
риск тот же, что в [оценке дирижёра](2026-11-13-supervisor-harness.md#риски):
тихая эрозия качества; лечится мандатом, бюджетом вмешательств и ручным
разбором первых прогонов.

### 3. Канал — свой, без своего приложения на первом шаге

**Telegram-бот:** пуш на iPhone, инлайн-кнопки под вариантами, свободный
текстовый ответ, ноль клиентского кода. Хост прогона сам опрашивает Bot
API исходящими запросами, VPS для этого не нужен. Токен бота — секрет в
окружении, не в репозитории.

Альтернатива без Telegram — **ntfy на VPS:** iOS-приложение, кнопки-действия
шлют POST на свой сервер. Для пушей на iOS self-hosted ntfy пересылает
через ntfy.sh идентификатор сообщения, но не его текст.

**Своё iOS-приложение — не первый шаг.** Это новый продукт на поддержке, а
узкое место не в нём. Оно оправдано, если чата не хватит для экрана уровня
плана («3/12, 1 запаркован, 2 ждут ответа»). Тогда это клиент relay на VPS
с APNs, и петлю переделывать не придётся.

## Одно изменение раннера: park & continue

Сейчас блок останавливает весь прогон с кодом 3
([цикл раннера](../design/runner.md#цикл-на-юнит)). Ночью ответ придёт
через несколько часов, и большой план всё это время стоит.

Изменение: заблокированный юнит паркуется, прогон идёт к следующему
готовому по `Depends:`, код 3 — только когда выполнять больше нечего.
Ответы человека применяются между прогонами: петля никогда не правит
файлы, пока прогон идёт. Новых ключей формата не нужно — `[!]` уже есть;
это поведение раннера, не рост формата.

## Чего не знаем

- **Классы стопов.** На Windows-машине лишь 4 события `run_end`, история —
  на Mac. [Пилот](2026-11-09-pilot-summary.md) дал 4 блока на 27 юнитов.
  Таблицу мандата подстраивать по `run_end.reason` из журналов событий всех
  проектов.
- **Хост прогона.** Машина с прогоном должна быть включена. VPS годится
  хостом только для проектов, собираемых на Linux; docflow с его
  Windows-проверками — не такой.
- **Надёжность разовых вызовов с полными правами** у `codex exec` и
  `opencode run` на длинном плане не проверялась.

## Порядок

1. **Пилот за вечер, без изменений docflow.** Петля (bash/PowerShell),
   бот через curl к Bot API, мандат как разовый промпт с JSON-ответом.
   Реальный сложный план. Записать: стопы, закрытые без человека, пуши,
   откаченные решения супервизора, расход супервизора.
2. **Если пилот зелёный:**
   - park & continue в раннере;
   - вместо жёсткого `osascript`/`notify-send`/`\a` — настраиваемая команда
     уведомления (обобщение существующего, не рост формата);
   - мандат — скилл.
3. **Петля в Go** (`docflow` сам ведёт супервизора) — новая CLI-команда
   упирается в заморозку формата; решение за человеком.
4. **Своё iOS-приложение** — только по итогам пилота, если не хватит
   чата.
