# Паритет CLI

Запускать из checkout. Нужны bash 3.2+, git и Go 1.24+.

```bash
bash tools/parity/run.sh bin/docflow              # bin/docflow против свежесобранного bin/docflow-go
bash tools/parity/run.sh bin/docflow bin/docflow-go   # два готовых бинарника
bash tools/parity/run.sh bin/docflow bin/docflow      # самопроверка одного бинарника
PARITY_SKIP='help' bash tools/parity/run.sh bin/docflow
```

Аргументы — пути к исполняемым файлам. `PARITY_SKIP` содержит имена сценариев
без `.sh`, разделённые пробельными символами. Если не запущено ни одного
сценария, харнесс завершается с кодом 2. Расхождение или ошибка сценария
дают код 1; полный паритет — 0.

## Формат сценария

`scenarios/<name>.sh` — bash-файл, подключаемый через `source` в отдельном
процессе с `set -euo pipefail`. Рабочий каталог — пустой временный каталог
репозитория. Минимальный сценарий:

```bash
parity_repo
docflow status || [ "$?" -eq 1 ]
```

`parity_repo` создаёт git-репозиторий с веткой `main` и начальным коммитом;
сценарий достраивает нужные файлы обычными shell-командами. Даты и авторы
коммитов фиксированы, системный и пользовательский git-конфиги отключены.
Не использовать текущее время, случайные данные и внешние сервисы.

Каждый вызов CLI должен идти через функцию `docflow`: она сохраняет
аргументы, stdout, stderr и код выхода, затем возвращает код вызова.
Ожидаемые ненулевые коды обрабатывать явно, как в примере.
Вызывать функцию в основном shell сценария: subshell, pipeline или
`$(docflow …)` теряют счётчик вызовов. Содержимое файлов, созданных CLI,
автоматически не сравнивается.

Для каждого сценария эталон и кандидат запускаются последовательно по
одному абсолютному пути, с заново созданными `HOME`, `CODEX_HOME` и
репозиторием. Окружение очищено, `DOCFLOW_NOTIFY=0`, stdin — `/dev/null`.
Пути в выводе не подменяются. На первом расхождении вызова печатается diff
и прогон останавливается. Временные каталоги удаляются при выходе.

## E2E-сценарии

Перенесённые acceptance-сюиты используют имена
`test_<suite>__<Class>__test_<case>.sh`. Каждый файл воспроизводит шаги
соответствующего исходного кейса. Общие shell-функции находятся в `e2e.sh`,
статические планы — в `fixtures/`.

`e2e_cli` сравнивает обычный вывод CLI, заменяя только время запуска,
интервал часов и длительность выполнения `run`. Число попыток, SHA,
стоимость, число replan и отказы сравниваются без изменений. `observe`
добавляет к сравнению содержимое файлов, историю Git и логи вызовов.
Сценарии раннера используют shell fake-агента из
`internal/agentio/testdata/fake_agent.sh`; уведомления перехватывают заглушки.

Bootstrap запускает `tools/install-dev.sh` из временного checkout с копией
выбранного исполняемого файла и ресурсов, с изолированным PATH и путями
с пробелами. Падение при commit воспроизводится через `SIGKILL` из
временного Git hook после создания коммита; затем CLI продолжает цикл
по сохранённому журналу. stdout, stderr и код завершения прерванного
вызова также сравниваются.
